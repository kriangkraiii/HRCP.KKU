# แผนงาน: ตรวจสอบความครบถ้วนก่อนส่งคำร้อง และระบบแนบไฟล์ประกอบการประเมินการสอน (Multiple File Attachments)

> **เอกสารแผนงาน**: `docs/PLAN-applicant-evaluation-files.md`  
> **สถานะ**: รอดำเนินการ (Planning Phase)  
> **ผู้รับผิดชอบหลัก**: `@[project-planner]`, `@[backend-specialist]`, `@[frontend-specialist]`

---

## 🎯 วัตถุประสงค์ (Objectives)

1. **ตรวจสอบความครบถ้วน 100% ก่อนส่งคำร้อง (Strict Pre-Submission Validation)**:
   - ผู้ยื่นคำร้อง (Applicant) จะต้องกรอกข้อมูลและบันทึกเอกสารจำเป็น (เอกสารที่ 0 บันทึกข้อความ และเอกสารที่ 1 แบบตรวจสอบเบื้องต้นพร้อมติ๊กครบทั้ง 5 ข้อ) ให้ครบถ้วนสมบูรณ์จริง ระบบจึงจะอนุญาตให้ส่งคำร้องได้
   - ป้องกันการส่งคำร้องหลุด (Bypass) ในฝั่ง Backend โดยเช็คความครบถ้วนระดับ Data Validation ก่อนเปลี่ยนสถานะจาก `DRAFT` เป็น `RECEIVED`
2. **ระบบแนบไฟล์ประกอบการประเมินผลการสอนแบบหลายไฟล์ (Multi-File Attachments on Evaluation Form)**:
   - ในหน้ากรอกแบบตรวจสอบเอกสารประกอบการประเมินผลการสอน (เอกสารที่ 1: `document_1_form.html`) ให้มีโซนสำหรับผู้ยื่นแนบไฟล์หลักฐาน (เช่น แผนการสอน, เอกสารประกอบการสอน, สื่อการสอน, ผลประเมินการสอนโดยนักศึกษา) ได้หลายไฟล์พร้อมกัน (Drag & Drop หรือ File Picker)
   - รองรับการแสดงรายการไฟล์ที่แนบแล้ว ขนาดไฟล์ วันที่อัปโหลด ปุ่มดาวน์โหลด และปุ่มลบไฟล์
   - ทางฝั่งผู้ดูแลระบบ (Admin) ในหน้ารายละเอียดคำร้องและ Fragment เอกสารที่ 1 จะสามารถดูและดาวน์โหลดไฟล์หลักฐานทั้งหมดที่ผู้ยื่นแนบมาได้สะดวก

## 📋 แผนการดำเนินงาน (Task Breakdown)

### ระยะที่ 1: Backend Validation & File Upload Endpoints
1. **`AcademicApplicantController.java`**:
   - ปรับปรุงเมธอด `submitRequest(@PathVariable Long id)`:
     - ตรวจสอบ `isDoc0Complete(docs)` และ `isDoc1Complete(docs)` อย่างเข้มงวด
     - หากข้อมูลยังไม่ครบ ให้ Redirect กลับพร้อมข้อความแจ้งเตือน `error=incomplete_documents`
   - เพิ่ม Endpoint สำหรับจัดการไฟล์แนบของผู้ยื่น:
     - `POST /user/academic/request/{id}/document-1/attachments`: รับ `MultipartFile[] files` สำหรับอัปโหลดหลายไฟล์พร้อมกัน
     - `GET /user/academic/request/{id}/attachment/{attachmentId}/download`: สำหรับผู้ยื่นดาวน์โหลดไฟล์แนบของตนเอง (พร้อมเช็คสิทธิ์ Applicant Security Ownership)
     - `POST /user/academic/request/{id}/attachment/{attachmentId}/delete`: สำหรับผู้ยื่นลบไฟล์แนบ (เฉพาะขณะที่สถานะยังเป็น `DRAFT`)
2. **`AcademicRequestService.java`**:
   - เพิ่มฟังก์ชันช่วยตรวจสอบความสมบูรณ์ของเอกสาร `validateRequestCompleteness(AcademicRequest request)`
   - รองรับการบันทึก `AcademicAttachment` หลายไฟล์พร้อมจัดเก็บ Path ลงระบบ Storage อย่างปลอดภัย

---

### ระยะที่ 2: Frontend UI/UX ในหน้ากรอกเอกสารที่ 1 (`document_1_form.html`)
1. **โซนแนบไฟล์ (Multi-File Dropzone & Upload List)**:
   - เพิ่มส่วน **"เอกสารแนบประกอบการประเมินผลการสอน"** ด้านล่างตารางรายการตรวจสอบ
   - ออกแบบ UI สไตล์ Drag & Drop Card พร้อมปุ่มเลือกไฟล์ได้หลายไฟล์ (`multiple`, รองรับ `.pdf`, `.docx`, `.doc`, `.zip`, `.rar`, `.pptx`)
   - แสดงตารางรายการไฟล์แนบแบบ Real-Time:
     - ไอคอนประเภทไฟล์ (PDF, Word, Zip, PowerPoint)
     - ชื่อไฟล์เดิม (Original Filename)
     - ขนาดไฟล์ที่อ่านง่าย (เช่น 2.4 MB)
     - วันที่และเวลาที่อัปโหลด
     - ปุ่มดาวน์โหลด และปุ่มลบไฟล์
2. **ตรวจสอบการติ๊กครบ 5 ข้อ และความถูกต้องของข้อมูล**:
   - ปรับปรุง JavaScript Client-side Validation:
     - ปุ่ม "บันทึกเอกสาร" จะปลดล็อคเมื่อกรอกชื่อผู้ยื่นและติ๊กเลือกครบทั้ง 5 รายการ
     - มี Alert แถบสีแจ้งสถานะความคืบหน้าอย่างชัดเจน (เช่น `✓ ติ๊กครบแล้ว 5/5 ข้อ`)

### ระยะที่ 3: Frontend ตรวจสอบความพร้อมในหน้าภาพรวม (`new_request.html`)
1. **Step Indicator & Checklist Card**:
   - แสดงสถานะความสมบูรณ์ของเอกสารที่ 0 และเอกสารที่ 1
   - แสดงจำนวนไฟล์แนบที่ผู้ยื่นได้อัปโหลดไว้แล้ว (เช่น `แนบไฟล์หลักฐานแล้ว 3 ไฟล์`)
2. **ปุ่มส่งคำร้อง (Submit Button & Confirmation Modal)**:
   - ตรวจสอบทั้ง Document 0, Document 1 ให้ครบถ้วนสมบูรณ์ก่อนเปิดให้กด "ส่งคำร้อง"
   - แสดงข้อความเตือนระบุชัดเจนว่ายังขาดเอกสารใดหากยังไม่ครบ

---

### ระยะที่ 4: ฝั่งผู้ดูแลระบบ (Admin View Integration)
1. **`doc_fragments/1.html` & `AcademicAdminController.java`**:
   - แสดงรายการไฟล์แนบที่ผู้ยื่นแนบมาในหน้ารายละเอียดคำร้องของแอดมิน
   - แอดมินสามารถเปิดดูตัวอย่าง (Preview) หรือดาวน์โหลดไฟล์แนบทั้งหมดได้ทันที

## 🧪 แผนการทดสอบและการตรวจสอบ (Verification Checklist)

- [ ] **Test 1 (Validation Gate)**: ทดลองยื่นคำร้องโดยที่ยังไม่ได้กรอกเอกสารที่ 0 หรือเอกสารที่ 1 หรือติ๊กไม่ครบ 5 ข้อ → ระบบต้องไม่อนุญาตให้ส่งคำร้อง
- [ ] **Test 2 (Multi-file Upload)**: ทดสอบอัปโหลดไฟล์หลักฐานพร้อมกันหลายไฟล์ (PDF, DOCX, ZIP) ในหน้า `document-1` → ไฟล์ถูกจัดเก็บถูกต้องและแสดงในตารางรายการไฟล์
- [ ] **Test 3 (File Download/Delete)**: ทดสอบดาวน์โหลดไฟล์แนบและลบไฟล์แนบในสถานะร่าง → ทำงานได้ถูกต้อง
- [ ] **Test 4 (Full Flow Submission)**: กรอกข้อมูลครบ 100% ติ๊กครบ 5 ข้อ และแนบไฟล์ → ส่งคำร้องสำเร็จ สถานะเปลี่ยนเป็น `RECEIVED`
- [ ] **Test 5 (Admin Verification)**: เข้าสู่ระบบด้วยบัญชี Admin แล้วเปิดดูคำร้อง → พบเอกสารที่ 1 ครบถ้วนพร้อมรายการไฟล์แนบทั้งหมดที่ผู้ยื่นอัปโหลดไว้
