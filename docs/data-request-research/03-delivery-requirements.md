# เอกสารแนบ ๒ — ข้อกำหนดการส่งมอบข้อมูล

ระบบ HRCP-KKU-Academic · วิทยาลัยการคอมพิวเตอร์ มหาวิทยาลัยขอนแก่น

---

## ๑. ช่องทางการส่งมอบ — ขอให้เลือก ๑ ช่องทาง

วิทยาลัยยินดีรับข้อมูลได้ทุกรูปแบบ เรียงลำดับตามที่จะเป็นประโยชน์สูงสุด
ขอให้ท่านเลือกช่องทางที่สะดวกที่สุดสำหรับระบบของท่าน

| ลำดับ | ช่องทาง | ข้อดี | สิ่งที่วิทยาลัยขอ |
|---|---|---|---|
| ๑ | **REST API (JSON)** | ข้อมูลตรงกันเสมอ ไม่ต้องส่งไฟล์ซ้ำ | URL endpoint, เอกสาร API, ข้อมูลยืนยันตัวตน, endpoint ทดสอบ (staging) |
| ๒ | **สิทธิ์อ่านฐานข้อมูล (read-only)** | ไม่ต้องพัฒนา API ใหม่ | บัญชีฐานข้อมูลสิทธิ์ `SELECT` เฉพาะมุมมอง (view) ที่ตกลงร่วมกัน + host/port/ชื่อฐานข้อมูล |
| ๓ | **ไฟล์อัตโนมัติผ่าน SFTP** | ตั้งครั้งเดียว ทำงานต่อเนื่อง | บัญชี SFTP หรือให้วิทยาลัยจัดเตรียมให้, ตกลงชื่อไฟล์และเวลาส่ง |
| ๔ | **ไฟล์ Excel ส่งเป็นครั้ง ๆ** | ทำได้ทันทีไม่ต้องพัฒนา | กรอกตามไฟล์ `แบบฟอร์มกรอกข้อมูลงานวิจัย.xlsx` ที่แนบมา (๑ ไฟล์ ๑๔ แผ่นงาน พร้อมแผ่นคำแนะนำ) |

> ช่องทางที่ ๔ เป็นทางเลือกสุดท้าย เพราะข้อมูลจะไม่อัปเดตอัตโนมัติ
> และต้องรบกวนท่านส่งไฟล์ใหม่ทุกครั้งที่มีผลงานเพิ่ม

## ๒. รูปแบบข้อมูล

ข้อกำหนดต่อไปนี้ใช้กับทุกช่องทาง เพื่อป้องกันข้อมูลเสียหายระหว่างนำเข้า

| หัวข้อ | ข้อกำหนด |
|---|---|
| **การเข้ารหัสอักขระ** | UTF-8 เท่านั้น — หากส่งเป็น CSV ขอให้มี BOM เพื่อให้ Microsoft Excel แสดงภาษาไทยได้ถูกต้อง (หากใช้ไฟล์ `.xlsx` ที่วิทยาลัยแนบมา ไม่ต้องกังวลเรื่องนี้) |
| **วันที่** | รูปแบบ ISO 8601 `YYYY-MM-DD` เป็น **คริสต์ศักราช** — หากระบบท่านเก็บเป็น พ.ศ. ขอให้แปลงหรือแจ้งให้ทราบ ส่วนฟิลด์ที่ระบุว่าเป็น พ.ศ. (`*_year_be`, `fiscal_year_be`) ให้ส่งเป็น พ.ศ. ตามชื่อฟิลด์ |
| **วันเวลา** | ISO 8601 พร้อม timezone เช่น `2026-08-07T14:30:00+07:00` |
| **ตัวเลข** | ไม่ใส่เครื่องหมายจุลภาคคั่นหลักพัน ใช้จุดเป็นจุดทศนิยม เช่น `1250000.50` ไม่ใช่ `1,250,000.50` |
| **ค่าตรรกะ (ใช่/ไม่ใช่)** | `Y` หรือ `N` (ไม่ใช้ `true`/`false`, `1`/`0`, `✓`) |
| **ค่าว่าง** | เว้นว่างไว้ (empty) — **ไม่ใช้** `-`, `N/A`, `ไม่มี`, `NULL` เป็นข้อความ |
| **หนึ่งเรื่องหนึ่งแถว** | ห้ามยุบข้อมูลหลายรายการรวมในเซลล์เดียว เช่น ผู้แต่ง ๕ คนต้องเป็น ๕ แถวในตาราง `OUTPUT_AUTHOR` ไม่ใช่ ๑ เซลล์คั่นจุลภาค (ยกเว้นฟิลด์ที่ระบุไว้ชัดว่าคั่นด้วย `;`) |
| **ชื่อคอลัมน์** | ไม่จำเป็นต้องตรงกับเอกสารแนบ ๑ — ขอเพียงแนบตารางเทียบว่าคอลัมน์ของท่านตรงกับฟิลด์ใด |
| **ไฟล์ Excel** | หากส่งเป็น `.xlsx` ขอให้ ๑ ตาราง = ๑ แผ่นงาน (sheet) หัวคอลัมน์อยู่แถวแรก ไม่มีเซลล์ผสาน (merged cells) ไม่มีแถวสรุปท้ายตาราง |

## ๓. ขอบเขตข้อมูล

| หัวข้อ | ขอบเขตที่เสนอ |
|---|---|
| **บุคลากร** | บุคลากรสายวิชาการทั้งคณะ (ขอทราบจำนวนโดยประมาณเพื่อประเมินปริมาณข้อมูล) |
| **ช่วงปีของผลงาน** | ย้อนหลัง **๑๐ ปี** นับจากปีปัจจุบัน |
| **ข้อยกเว้น** | ผลงานที่เคยใช้เสนอขอตำแหน่งทางวิชาการ — ขอ **โดยไม่จำกัดปี** เพราะแบบฟอร์มต้องแสดงประวัติทั้งหมด |
| **โครงการวิจัย/ทุน** | ย้อนหลัง ๑๐ ปี ทั้งที่ดำเนินการอยู่และแล้วเสร็จ |
| **ตัวชี้วัด (Scopus/h-index)** | ค่าล่าสุด พร้อมวันที่นับข้อมูล |

หากขอบเขตนี้ทำให้ปริมาณข้อมูลมากเกินไป หรือมีข้อจำกัดด้านระเบียบ
ขอหารือปรับได้ตามความเหมาะสม

## ๔. ความถี่การอัปเดต

| ครั้ง | รายละเอียด |
|---|---|
| **ครั้งแรก** | ส่งข้อมูลทั้งหมดตามขอบเขต (full load) |
| **หลังจากนั้น** | ส่งเฉพาะรายการที่เพิ่ม/แก้ไข (incremental) — วันละครั้ง เวลาประมาณ ๐๒:๐๐ น. |

การส่งแบบ incremental ต้องอาศัยฟิลด์ `updated_at` ในทุกตาราง
จึงขอความอนุเคราะห์ฟิลด์นี้เป็นพิเศษ หากระบบท่านไม่มี วิทยาลัยจะดึงข้อมูลทั้งหมดใหม่
ทุกคืนแทน (จะใช้ทรัพยากรฝั่งท่านมากกว่า)

## ๕. ความปลอดภัยและการยืนยันตัวตน

| หัวข้อ | ข้อกำหนด |
|---|---|
| **การเข้ารหัสระหว่างรับส่ง** | TLS 1.2 ขึ้นไป (HTTPS / SFTP) |
| **การยืนยันตัวตน** | API key ใน HTTP header หรือ OAuth 2.0 client credentials — วิทยาลัยรับได้ทั้งสองแบบ |
| **การจำกัดต้นทาง** | วิทยาลัยยินดีให้ท่านจำกัดการเข้าถึงเฉพาะ IP ของเครื่องแม่ข่ายระบบ HRCP (จะแจ้งเป็นลายลักษณ์อักษรเมื่อตกลงช่องทางแล้ว) |
| **สิทธิ์ที่ขอ** | อ่านอย่างเดียว (read-only) เท่านั้น ไม่ขอสิทธิ์เขียน แก้ไข หรือลบ |
| **ช่องทางที่ไม่ใช้** | ไม่ส่งข้อมูลผ่านอีเมลแบบไม่เข้ารหัส, ไม่ส่งผ่านแอปพลิเคชันแชท, ไม่ใช้ลิงก์แชร์ไฟล์แบบสาธารณะ |
| **การจัดเก็บข้อมูลยืนยันตัวตน** | เก็บใน environment variable ของเครื่องแม่ข่าย ไม่บันทึกลงในซอร์สโค้ดหรือระบบควบคุมเวอร์ชัน |

## ๖. การคุ้มครองข้อมูลส่วนบุคคล (PDPA)

| หัวข้อ | รายละเอียด |
|---|---|
| **วัตถุประสงค์** | เติมข้อมูลในคำขอกำหนดตำแหน่งทางวิชาการ **ของเจ้าของข้อมูลเอง** เท่านั้น |
| **สิ่งที่จะไม่ทำ** | ไม่ใช้ประเมินผลการปฏิบัติงาน ไม่จัดอันดับบุคลากร ไม่เปิดเผยข้อมูลผลงานของผู้อื่นต่อผู้ยื่นคำขอ ไม่ส่งต่อบุคคลที่สาม |
| **ผู้เข้าถึงได้** | (๑) เจ้าของข้อมูล (๒) เจ้าหน้าที่งานบุคคลที่ได้รับมอบหมาย ในขั้นตอนตรวจสอบเอกสารเท่านั้น |
| **การบันทึกการเข้าถึง** | ระบบบันทึกทุกครั้งที่มีการเรียกดูข้อมูล (audit log) |
| **ระยะเวลาเก็บ** | ตลอดระยะเวลาที่คำขอกำหนดตำแหน่งยังอยู่ในกระบวนการ และเก็บต่อตามระเบียบงานสารบรรณของมหาวิทยาลัย |
| **สิทธิของเจ้าของข้อมูล** | ผู้ยื่นคำขอเห็นข้อมูลที่ดึงมาทั้งหมด และแก้ไข/ลบ/ปฏิเสธการใช้ข้อมูลรายการใดก็ได้ ก่อนส่งคำขอ |
| **ข้อมูลที่ไม่ขอ** | เลขบัตรประจำตัวประชาชนฉบับเต็ม, เงินเดือน, ข้อมูลสุขภาพ, ข้อมูลอ่อนไหวตามมาตรา ๒๖ |
| **เอกสารเพิ่มเติม** | วิทยาลัยพร้อมจัดทำข้อตกลงการใช้ข้อมูล (Data Use Agreement) และแบบแสดงความยินยอมของเจ้าของข้อมูล หากท่านกำหนด |

## ๗. สิ่งที่ขอเพิ่มเติมนอกจากตัวข้อมูล

1. **พจนานุกรมข้อมูลหรือแผนภาพความสัมพันธ์ (ERD) ของระบบต้นทาง** (หากมี)
   เพื่อเทียบกับเอกสารแนบ ๑ และลดความคลาดเคลื่อนในการตีความ
2. **ข้อมูลตัวอย่างจริง ๕–๑๐ รายการ** (ปิดบังชื่อได้) ก่อนเชื่อมต่อจริง
   เพื่อทดสอบโครงสร้างและรูปแบบวันที่/ตัวเลข
3. **รายการฟิลด์ที่ระบบของท่านไม่มี** — ข้อนี้สำคัญเท่ากับข้อมูลที่ให้มา
   เพราะวิทยาลัยต้องออกแบบว่าช่องใดยังต้องให้ผู้ยื่นคำขอกรอกเอง
4. **ไฟล์ผลงานฉบับเต็ม** — ระบบต้นทางเก็บไฟล์ PDF ของผลงานไว้หรือไม่
   หากมี ขอหารือว่าจะให้เป็น URL หรือวิธีดึงไฟล์แบบใด
   (ระบบ HRCP รองรับไฟล์ขนาดไม่เกิน ๑๐ MB ต่อไฟล์)
5. **ชื่อผู้ประสานงาน** — ผู้ดูแลระบบต้นทาง และผู้มีอำนาจอนุมัติสิทธิ์เข้าถึง

## ๘. คุณภาพข้อมูลที่ขอ

| หัวข้อ | ข้อกำหนด |
|---|---|
| **ความครบถ้วน** | ฟิลด์ระดับ **M** ต้องมีค่าทุกแถว หากบางแถวไม่มี ขอให้ส่งมาพร้อมระบุว่าขาด อย่าตัดแถวนั้นออก |
| **ความไม่ซ้ำ** | `output_id` ต้องไม่ซ้ำกันในตาราง `RESEARCH_OUTPUT` — หากผลงานเดียวถูกบันทึกซ้ำในระบบต้นทาง ขอให้แจ้งเพื่อวิทยาลัยจะจัดการตรวจซ้ำด้วย DOI/ชื่อผลงาน |
| **ความสอดคล้อง** | `researcher_id` และ `output_id` ที่อ้างในตารางลูกต้องมีอยู่ในตารางแม่จริง |
| **ผู้ประพันธ์อันดับแรก** | หนึ่งผลงานควรมี `is_first_author = Y` ไม่เกินหนึ่งคน (หากมีมากกว่าหนึ่งเพราะเป็น co-first author ขอให้แจ้ง) |

## ๙. สิ่งที่วิทยาลัยจะดำเนินการฝ่ายเรา

เพื่อความโปร่งใส ขอเรียนให้ทราบข้อจำกัดปัจจุบันของระบบ HRCP และแผนแก้ไข

1. **ระบบ HRCP ยังไม่มีคอลัมน์รหัสพนักงาน** — ปัจจุบันใช้อีเมลเป็นตัวระบุผู้ใช้เพียงอย่างเดียว
   วิทยาลัยจะเพิ่มฟิลด์รหัสพนักงานในฐานข้อมูลผู้ใช้ เพื่อรองรับการจับคู่ข้อมูลกับระบบของท่าน
2. **หากไม่ได้รับรหัสพนักงาน** — จะใช้อีเมล @kku.ac.th เป็นกุญแจสำรอง
   โดยรับทราบความเสี่ยงว่าอีเมลอาจเปลี่ยนได้
3. **ระบบยังไม่มีตารางหน่วยงาน** — ปัจจุบันให้ผู้ยื่นพิมพ์ชื่อคณะ/ภาควิชาเป็นข้อความอิสระ
   วิทยาลัยจะสร้างตารางหน่วยงานโดยใช้รหัสตามที่ท่านให้มา (ตาราง A2)
4. **การตรวจทานโดยเจ้าของข้อมูล** — ข้อมูลที่ดึงมาจะแสดงเป็น "ร่าง" ให้ผู้ยื่นคำขอ
   ตรวจสอบและแก้ไขได้ทุกช่องก่อนส่ง ระบบจะไม่ส่งคำขอด้วยข้อมูลที่ยังไม่ได้รับการยืนยัน
