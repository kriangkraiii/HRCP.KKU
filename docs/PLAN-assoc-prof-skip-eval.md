**ไฟล์แผนงาน:** `docs/PLAN-assoc-prof-skip-eval.md`  
**สถานะ:** เสร็จสมบูรณ์ (Implemented & Verified 100%)  
**ผู้รับผิดชอบหลัก:** `project-planner`, `backend-specialist`, `frontend-specialist`

## 1. ที่มาและความต้องการ (Context & Requirements)

### 1.1 ปัญหาและข้อเท็จจริงในระบบปัจจุบัน
1. ตามหลักเกณฑ์การขอกำหนดตำแหน่งทางวิชาการ (ก.พ.อ. และ มข.):
   - การขอตำแหน่ง **ผู้ช่วยศาสตราจารย์ (ผศ.)** และ **รองศาสตราจารย์ (รศ.)** ต้องผ่านการประเมินผลการสอน (Teaching Evaluation - Phase 1)
   - การขอตำแหน่ง **ศาสตราจารย์ (ศ.)** สำหรับผู้ที่ดำรงตำแหน่ง **รองศาสตราจารย์ (รศ.)** อยู่แล้ว **ได้รับการยกเว้นไม่ต้องผ่านการประเมินผลการสอน** โดยสามารถยื่นคำขอตำแหน่งทางวิชาการ (Position Request - Phase 2) ได้โดยตรง
2. ในระบบปัจจุบัน:
   - ฝั่งคำขอตำแหน่งทางวิชาการ (Phase 2) มีปุ่มและ Endpoint `create-professor-request` รองรับการขอตำแหน่ง ศ. โดยไม่ต้องมีผลประเมินอยู่แล้ว
   - **แต่ในหน้ายื่นประเมินการสอน (Phase 1):** อาจารย์ที่ดำรงตำแหน่ง รศ. ยังคงเห็นปุ่ม "ยื่นคำร้องขอการประเมินการสอน" บน Dashboard และเมื่อกดเข้าไป ระบบยังสร้างแบบร่างคำร้องประเมินการสอนให้ แต่เมื่อเข้าสู่เอกสารที่ 1 (`document_1_form.html`) ช่องติ๊กเลือกตำแหน่ง ผศ. และ รศ. จะถูกปิดใช้งาน (Disabled) ทั้งหมด ทำให้ผู้ยื่นเกิดความสับสนและไม่สามารถดำเนินการต่อได้

### 1.2 วัตถุประสงค์
1. **ป้องกันการสร้างคำร้องประเมินการสอนซ้ำซ้อน:** บล็อกไม่ให้อาจารย์ที่ดำรงตำแหน่ง รศ. (และ ศ.) สร้างคำร้องประเมินการสอนใน Phase 1
2. **แนะนำเส้นทางและส่งต่อไปยัง Phase 2 โดยตรง:** แสดงแบนเนอร์แจ้งเตือนและปุ่มนำทางให้อาจารย์ตำแหน่ง รศ. ไปยื่นคำขอตำแหน่งศาสตราจารย์ได้ทันที ทั้งในหน้า Academic Dashboard และหน้าสร้างคำร้อง
3. **ตรวจสอบสิทธิ์การขอ ศ. ใน Phase 2 อย่างรัดกุม:** ตรวจสอบให้แน่ใจว่าผู้ที่จะขอตำแหน่ง ศ. โดยไม่ใช้ผลประเมิน ต้องมีตำแหน่งปัจจุบันเป็น "รองศาสตราจารย์" เท่านั้น

## 3. แผนการดำเนินงาน (Task Breakdown)

### Task 1: ปรับปรุง Backend Controller สำหรับการบล็อกและส่งต่อคำร้องประเมิน (`backend-specialist`)
- **ไฟล์:** `HRCP-KKU-Academic/src/main/java/com/ecom/academic/controller/AcademicApplicantController.java`
- **การเปลี่ยนแปลง:**
  1. ในหน้า `dashboard`: ส่งค่า `isAssociateProfessor` หรือ `currentRank` ไปยัง Model
  2. ในเมธอด `newRequestForm` (`/new-request`): ตรวจสอบ `AcademicRankPolicy.currentRank(user)`
     - หากเป็น `ASSOCIATE_PROFESSOR`: redirect ไปยัง `/user/position/new-request` หรือ `/user/academic/dashboard?info=professor_no_eval`
     - หากเป็น `PROFESSOR`: redirect ไปยัง `/user/academic/dashboard?error=highest_rank`
  3. ในเมธอด `submitDocument1`: ตรวจสอบซ้ำ หากเป็น รศ. ให้บล็อกการบันทึกเอกสารประเมินการสอน
- **INPUT:** คำร้องประเมินการสอนจากอาจารย์ตำแหน่ง รศ.
- **OUTPUT:** ระบบปฏิเสธการสร้างคำร้องประเมิน และส่งต่อไปยังขั้นตอนขอตำแหน่ง ศ. โดยอัตโนมัติ
- **VERIFY:** เขียน Unit Test ทดสอบการเข้าถึง `/new-request` ด้วยผู้ใช้ตำแหน่ง รศ.

### Task 2: ปรับปรุง UI หน้า Dashboard ของผู้ยื่นคำร้อง (`frontend-specialist`)
- **ไฟล์:** `HRCP-KKU-Academic/src/main/resources/templates/academic/applicant/dashboard.html`
- **การเปลี่ยนแปลง:**
  1. เมื่อผู้ใช้มีตำแหน่งเป็น **รองศาสตราจารย์**:
     - แสดง Alert/Card สีเขียวเด่นชัด:
       `🎓 ท่านดำรงตำแหน่งรองศาสตราจารย์: การขอกำหนดตำแหน่งศาสตราจารย์ (ศ.) ไม่ต้องผ่านการประเมินผลการสอน ท่านสามารถยื่นคำขอตำแหน่งทางวิชาการได้ทันที`
     - มีปุ่ม Action: `[ <i class="fas fa-arrow-right"></i> ยื่นขอตำแหน่งศาสตราจารย์ ]` เชื่อมโยงไปยังแท็บตำแหน่งทางวิชาการ หรือ `/user/position/new-request`
     - ปรับปุ่ม "ยื่นคำร้องขอการประเมินการสอน" ให้เป็นปุ่มแนะนำหรือซ่อนปุ่ม เพื่อไม่ให้เกิดความสับสน
- **INPUT:** ค่า `currentRank` จาก Backend
- **OUTPUT:** หน้า Dashboard สื่อสารชัดเจนและนำทางอาจารย์ รศ. ได้อย่างถูกต้อง
- **VERIFY:** เปิดหน้า Dashboard ด้วยบัญชีอาจารย์ รศ. และตรวจสอบการแสดงผล

### Task 3: ปรับปรุงหน้าแบบฟอร์มเอกสาร 1 ป้องกันข้อผิดพลาด (`frontend-specialist`)
- **ไฟล์:** `HRCP-KKU-Academic/src/main/resources/templates/academic/applicant/document_1_form.html`
- **การเปลี่ยนแปลง:**
  1. หากผู้ใช้เป็น รศ. (`associateBlocked` เป็นจริง):
     - แสดง Alert กล่องใหญ่ด้านบนของส่วนเลือกตำแหน่ง:
       `ท่านดำรงตำแหน่งรองศาสตราจารย์อยู่แล้ว การขอตำแหน่งศาสตราจารย์ไม่ต้องประเมินการสอน [คลิกที่นี่เพื่อไปยื่นขอตำแหน่งศาสตราจารย์]`
     - ซ่อนปุ่ม "บันทึกเอกสาร" หรือปิดการทำงานเพื่อป้องกันการกรอกข้อมูลค้าง
- **INPUT:** เอกสารที่ 1 ของคำร้องเดิม
- **OUTPUT:** คำแนะนำที่ชัดเจน ไม่ปล่อยให้อาจารย์ติดอยู่ในฟอร์มที่ส่งไม่ได้
- **VERIFY:** ทดสอบเปิดหน้าเอกสารที่ 1 ด้วยบัญชี รศ.

### Task 4: ตรวจสอบความรัดกุมของเงื่อนไขขอตำแหน่ง ศ. ใน Phase 2 (`backend-specialist`)
- **ไฟล์:** `HRCP-KKU-Academic/src/main/java/com/ecom/academic/service/PositionRequestService.java`
- **การเปลี่ยนแปลง:**
  1. ตรวจสอบเมธอด `rankProblemForProfessor`:
     - ต้องเป็น `AcademicRank.ASSOCIATE_PROFESSOR` เท่านั้นจึงจะขอตำแหน่ง ศ. ได้
     - หากเป็นอาจารย์ (Lecturer) หรือ ผศ. พยายามเรียก endpoint `/create-professor-request` จะต้องถูกปฏิเสธ
- **INPUT:** คำขอตำแหน่ง ศ. จากตำแหน่งต่างๆ
- **OUTPUT:** มีเพียง รศ. เท่านั้นที่ขอ ศ. ได้โดยตรง
- **VERIFY:** รัน Unit Test ตรวจสอบสิทธิ์การขอ ศ.

## 4. ข้อพิจารณาและคำถามเพื่อความชัดเจน (Socratic Questions for User)

1. **พฤติกรรมเมื่ออาจารย์ตำแหน่ง รศ. กดปุ่ม "ยื่นคำร้องขอการประเมินการสอน" หรือเข้าสู่หน้าประเมินการสอน:**
   - **ตัวเลือก A (แนะนำ):** แสดงกล่องแจ้งเตือนบนหน้า Dashboard ทันทีว่า *"ท่านดำรงตำแหน่งรองศาสตราจารย์แล้ว ไม่ต้องยื่นประเมินการสอน สามารถยื่นขอตำแหน่ง ศ. ได้ทันที"* และเปลี่ยนปุ่มหลักเป็น **"ยื่นขอตำแหน่งศาสตราจารย์ (ศ.)"** พาไปยังหน้าคำขอตำแหน่ง (Phase 2) โดยตรง
   - **ตัวเลือก B:** ซ่อนปุ่มยื่นประเมินการสอน และหากกดลิงก์เข้ามา ให้ Redirect ไปยังหน้ายื่นขอตำแหน่งศาสตราจารย์ทันที
2. **กรณีผู้ใช้เดิมที่มีตำแหน่งเป็น รศ. แต่มีคำร้องประเมินการสอนฉบับร่างค้างอยู่ในระบบ:**
   - ต้องการให้ระบบแสดงปุ่ม "ยกเลิกแบบร่างคำร้อง" พร้อมแนะนำให้ไปยื่นขอ ศ. ในหน้าคำขอตำแหน่งทางวิชาการ หรือให้ระบบแจ้งเตือนอย่างไร?
3. **การตรวจสอบตำแหน่งปัจจุบัน:**
   - ปัจจุบันระบบอ่านตำแหน่งวิชาการจาก Profile (ที่ซิงค์จากระบบ HR) เช่น "รองศาสตราจารย์" ถูกต้องหรือไม่?
