# แผนรับมือเหตุการณ์ความมั่นคงปลอดภัย (Incident Response Plan - IRP)
**ระบบ HRCP.KKU — มาตรฐาน ISO/IEC 27001:2022 (Control 5.24 - 5.28)**

---

## 1. วัตถุประสงค์
เพื่อกำหนดขั้นตอนการปฏิบัติการเมื่อเกิดเหตุการณ์ความมั่นคงปลอดภัยสารสนเทศ (Security Incident) อย่างมีแบบแผน รวดเร็ว และลดผลกระทบต่อการให้บริการ

---

## 2. ขั้นตอนการจัดการเหตุการณ์ 5 ขั้นตอน (5-Stage Incident Lifecycle)

```
[1. Detection & Reporting] ➔ [2. Triage & Analysis] ➔ [3. Containment & Mitigation] ➔ [4. Eradication & Recovery] ➔ [5. Post-Incident Review]
```

### ขั้นที่ 1: การตรวจจับและรายงาน (Detection & Reporting)
- ตรวจพบผ่าน: System Logs, Error Alerts, รายงานจากผู้ใช้, หรือ Security Monitoring
- ช่องทางแจ้งเหตุ: Email ถึงผู้ดูแลระบบหรือระบบ Ticket ภายใน

### ขั้นที่ 2: การคัดกรองและวิเคราะห์ (Triage & Analysis)
- จัดระดับความรุนแรง:
  - **P1 (Critical):** ระบบหยุดทำงานทั้งหมด, ข้อมูลรั่วไหลภายนอก, ถูกเข้าถึงสิทธิ์ Admin โดยไม่ได้รับอนุญาต (ตอบสนองภายใน 1 ชั่วโมง)
  - **P2 (High):** ฟังก์ชันสำคัญทำงานไม่ได้, ตรวจพบการพยายามโจมตีที่ผ่านชั้นแรกได้ (ตอบสนองภายใน 4 ชั่วโมง)
  - **P3 (Medium/Low):** พฤติกรรมผิดปกติที่ไม่กระทบการทำงานหลัก (ตอบสนองภายใน 24 ชั่วโมง)

### ขั้นที่ 3: การควบคุมและจำกัดความเสียหาย (Containment & Mitigation)
- ระงับบัญชีที่ถูกเจาะชั่วคราว (`is_enable = false`)
- บล็อก IP ผู้โจมตีผ่าน Firewall หรือ Rate Limiter
- สลับโหมดการยืนยันตัวตนเป็น SSO อย่างเดียว (`app.auth.mode=production`)

### ขั้นที่ 4: การกำจัดต้นตอและการฟื้นฟูระบบ (Eradication & Recovery)
- อัปเดตแพตช์/แก้ไขโค้ดช่องโหว่
- ตรวจสอบความถูกต้องของฐานข้อมูลและกู้คืนจาก Backup ที่ปลอดภัย
- รีเซ็ต Credentials และ Session ทั้งหมดของผู้เกี่ยวข้อง

### ขั้นที่ 5: การสรุปบทเรียนและปรับปรุง (Post-Incident Review)
- จัดทำรายงานสรุปเหตุการณ์ (Incident Report) ภายใน 3 วันทำการ
- ปรับปรุงมาตรการควบคุมเพื่อป้องกันการเกิดซ้ำ
