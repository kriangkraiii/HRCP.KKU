# แผนงาน: แก้ไขปัญหาลายเซ็นถูกตัดส่วนบนในเอกสาร PDF (Fix Signature Cropping in Document Generation)

> เอกสารแผนงานตามคำสั่ง /plan สำหรับการแก้ไขปัญหาการตัดขอบลายเซ็น (ลายเซ็นไม่เต็ม) ในระบบสร้างเอกสารราชการ

---

## 1. วัตถุประสงค์ (Objective)
แก้ไขปัญหารูปภาพลายเซ็นดิจิทัลถูกตัดส่วนบน (Top Clipped / ลายเซ็นไม่เต็ม) เมื่อระบบนำลายเซ็นไปประทับลงในเอกสารแบบฟอร์ม (เช่น doc_1.docx) และแปลงเป็นไฟล์ PDF ส่งผลให้เส้นตวัดด้านบนของลายเซ็นขาดหายไป เพื่อให้ลายเซ็นในเอกสารจริงมีความสมบูรณ์คมชัดครบถ้วนเหมือนกับภาพต้นฉบับในระบบ

---

## 2. การวิเคราะห์สาเหตุเชิงลึก (Root Cause Analysis)

จากการตรวจสอบภาพหน้าจอระบบที่ผู้ใช้ส่งมาเปรียบเทียบกับไฟล์ลายเซ็นต้นฉบับและโค้ดของระบบสร้างเอกสาร พบสาเหตุที่แท้จริงดังนี้:

### 2.1 ภาพลายเซ็นต้นฉบับสมบูรณ์ 100%
- ในแผงเลือกและดูตัวอย่างลายเซ็นด้านขวาของหน้าจอ ลายเซ็นของผู้ใช้แสดงผลเต็มทั้งรูปภาพ มีเส้นตวัดด้านบนครบถ้วน ไม่ได้เกิดจากการวาดหรือไฟล์รูปภาพเสียหายแต่อย่างใด

### 2.2 ปัญหาเกิดจาก OpenXML Line Spacing ใน DocumentGenerationService
- ใน `DocumentGenerationService.java` ฟังก์ชัน `withFixedSignatureHeight`:
  ```xml
  <w:spacing w:before="0" w:after="0" w:line="680" w:lineRule="exact"/>
  ```
- มีการกำหนดความสูงของบรรทัดลายเซ็นไว้ตายตัวที่ `680 twips` (เทียบเท่า 34 pt หรือ 1.2 ซม.) ด้วยคุณสมบัติ `w:lineRule="exact"`
- วัตถุประสงค์เดิมของ `exact` คือเพื่อให้ช่องที่มีลายเซ็นและช่องว่าง (Padding) ของผู้ลงนามอีกคนที่ยังไม่ได้เซ็น มีความสูงเท่ากันเป๊ะ ทำให้ชื่อและตำแหน่งในแถวเดียวกันอยู่ในระดับเดียวกัน

### 2.3 สาเหตุที่ทำให้ภาพถูกตัดขอบบน (Clipping)
1. บรรทัดลายเซ็นถูกสร้างโดยคัดลอก Paragraph Properties (`pPr`) มาจากบรรทัดชื่อ (`namePara`) ซึ่งมีขนาดฟอนต์ข้อความ (TH Sarabun New 16pt)
2. ฟอนต์ขนาด 16pt จะมีระยะใต้เส้นฐานตัวอักษร (Baseline Descent) ประมาณ 8-10pt
3. รูปภาพลายเซ็น (`<wp:inline>`) วางอยู่บน Baseline และมีความสูงเต็มเพดาน `SIGNATURE_MAX_HEIGHT_EMU` (432,000 EMU = 34 pt = 680 twips)
4. เมื่อ Baseline อยู่สูงจากขอบล่าง 8-10pt ทำให้พื้นที่ว่างเหนือ Baseline ภายในกรอบบรรทัด 34pt เหลือเพียงประมาณ 24-26pt เท่านั้น
5. ตามมาตรฐานของ OpenXML และ LibreOffice / MS Word: หากองค์ประกอบในบรรทัดมีความสูงเกินขนาดบรรทัดที่ตั้งค่าเป็น `w:lineRule="exact"` ระบบเรนเดอร์จะตัด (Clip) ส่วนที่ล้นเกินกรอบด้านบนออกทันที
6. ผลลัพธ์คือ ลายเซ็นถูกเฉือนส่วนบนออกไปประมาณ 25-30% ตามภาพที่ผู้ใช้พบในเอกสาร doc_1.docx

### 2.4 เหตุใดเอกสารบางฉบับจึงไม่พบปัญหานี้
- ในเอกสารที่มีเส้นจุดประ "ลงชื่อ ......" เช่น `doc_0.docx` ระบบจะใช้ฟังก์ชัน `stampOntoSignatureLine` ซึ่งลบจุดประแล้วแทนที่ด้วยภาพ โดยไม่ได้กำหนด `withFixedSignatureHeight(w:lineRule="exact")` บรรทัดจึงขยายความสูงตามรูปภาพได้ตามธรรมชาติ ทำให้ลายเซ็นไม่ถูกตัดขอบบน

## 3. แนวทางแก้ไขที่เสนอ (Proposed Solution)

### แนวทางที่ 1: ปรับคุณสมบัติการจัดระยะบรรทัดเป็น atLeast
- เปลี่ยนจาก `w:lineRule="exact"` เป็น `w:lineRule="atLeast"` ใน `withFixedSignatureHeight`:
  ```xml
  <w:spacing w:before="0" w:after="0" w:line="680" w:lineRule="atLeast"/>
  ```
- **ผลลัพธ์:** LibreOffice / MS Word จะกำหนดให้ความสูงของบรรทัดมีขนาด "อย่างน้อย" 680 twips (ทำให้ช่องว่างที่ยังไม่ได้เซ็นยังคงรักษาระยะความสูง 680 twips ไว้เพื่อจัดระดับให้เท่ากัน) แต่ในช่องที่มีลายเซ็น บรรทัดจะยอมให้ส่วนบนขยายขึ้นได้โดยไม่ทำการตัดขอบภาพ (No Clipping)

### แนวทางที่ 2: กำหนดขนาดฟอนต์ในบรรทัดลายเซ็นให้มีขนาดเล็กที่สุด (Font Descent Elimination)
- ในพารากราฟที่สร้างสำหรับใส่ลายเซ็นและพารากราฟช่องว่าง ให้กำหนดขนาดฟอนต์ระดับต่ำสุด เช่น `<w:rPr><w:sz w:val="2"/><w:szCs w:val="2"/></w:rPr>` หรือล้างระยะเยื้องที่ไม่จำเป็นออก
- **ผลลัพธ์:** ขจัดปัญหาระยะ Baseline Descent ที่กินพื้นที่ด้านล่าง ทำให้ภาพลายเซ็นและช่องว่างมีขนาดตรงกันอย่างสมบูรณ์ที่สุด

## 4. แผนการดำเนินงาน (Task Breakdown)

### ส่วนที่ 1: ปรับปรุงโค้ด DocumentGenerationService.java
- ปรับฟังก์ชัน `withFixedSignatureHeight` ใน `src/main/java/com/ecom/academic/service/DocumentGenerationService.java`
  - เปลี่ยน `w:lineRule="exact"` เป็น `w:lineRule="atLeast"`
  - จัดการขนาดฟอนต์ในพารากราฟลายเซ็นและสเปเซอร์ไม่ให้ดันระยะบรรทัดเกินความจำเป็น

### ส่วนที่ 2: ปรับปรุงและตรวจสอบ Unit Tests
- อัปเดตการตรวจสอบใน `src/test/java/com/ecom/academic/service/SignatureStampingTest.java`
  - ปรับปรุงค่าคงที่ `FIXED_LINE` จาก `w:lineRule="exact"` เป็น `w:lineRule="atLeast"`
  - ตรวจสอบว่าเทสต์ทุกเคสผ่านการทำงานเรียบร้อย (เซ็นช่องเดียว, เซ็นสองช่อง, ความสูงระดับเดียวกัน)

### ส่วนที่ 3: การทดสอบ Render จริงและแปลงเป็น PDF (E2E Verification)
- ทำการเรนเดอร์เอกสาร `doc_1.docx` โดยนำภาพลายเซ็นจริงที่มีเส้นตวัดด้านบนมาประทับ
- สั่งแปลงไฟล์ DOCX เป็น PDF ด้วย LibreOffice ในเครื่อง
- แปลงหน้า PDF เป็นรูปภาพและตรวจสอบความสมบูรณ์ของลายเซ็นด้วยสายตา เพื่อยืนยันว่าไม่มีการตัดขอบบนอีกต่อไป
