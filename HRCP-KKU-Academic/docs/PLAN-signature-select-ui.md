## 1. ข้อมูลและปัญหาที่พบ (Overview & Problem Statement)

### 1.1 ปัญหาปัจจุบัน (Current Problem)
ผู้ใช้แจ้งข้อเสนอแนะ:
> *"ตอนเลือกลายเซ็นว่าจะเซ็น ผู้ใช้ไม่รู้ว่าเลือกอันไหนที่จะเซ็น UI ไม่ชัดเจน"*

เมื่อตรวจสอบหน้าลงนามเอกสาร (`/esign/sign/{stepId}` ในไฟล์ `templates/academic/esign/sign.html`):
1. **ขาดความชัดเจนของสถานะที่ถูกเลือก (Ambiguous Checked State):**
   - การเลือกลายเซ็นใช้ Bootstrap `.btn-check` ร่วมกับป้ายกำกับ `.btn.btn-outline-secondary`
   - เมื่อวิทยุถูกเลือก (Checked) ปุ่มจะเปลี่ยนเป็นพื้นหลังสีเทาเข้ม (`#6c757d`) ซึ่งสีเทาในหลักสากล UX มักสื่อถึง **"สถานะปิดใช้งาน (Disabled)"** มากกว่าสถานะกำลังเลือกใช้งาน
   - ไม่มีเครื่องหมายติ๊กถูก (Checkmark icon ✓) กำกับบนการ์ด
   - ไม่มีป้ายข้อความกำกับว่า **"กำลังเลือกใช้อันนี้" (Currently Selected)**
2. **ไม่ทราบว่าอันไหนคือลายเซ็นหลัก/ค่าเริ่มต้น (Missing Default Indicator):**
   - ผู้ใช้อาจมีหลายลายเซ็นที่บันทึกไว้ในระบบ แต่หน้าลงนามไม่ได้แสดงป้าย `ลายเซ็นหลัก (Default)` ให้เห็น ทำให้ไม่ทราบว่าระบบเลือกอันไหนไว้ให้ตั้งแต่แรก
3. **ขาดความเชื่อมโยงกับตำแหน่งและบริบทการลงนาม (Lack of Contextual Clarity):**
   - กล่องเลือกลายเซ็นระบุเพียงข้อความสั้น ๆ ว่า *"เลือกลายเซ็น"* แต่ไม่ได้สรุปให้ผู้ใช้เห็นชัดเจนว่า **"ลายเซ็นนี้จะถูกนำไปประทับในตำแหน่งใด"** (เช่น ผู้ขอรับการประเมิน / ประธานสาขาวิชา / คณบดี) และใครเป็นเจ้าของลายเซ็น
4. **ขาดกล่องสรุปยืนยันแบบไดนามิก (No Dynamic Confirmation Banner):**
   - เมื่อผู้ใช้คลิกเลือกระหว่างลายเซ็นที่ 1 หรือ 2 ไม่มีการตอบสนองหรือแถบสรุปที่แจ้งเตือนแบบ Real-time ว่าขณะนี้ระบบได้สลับไปใช้ลายเซ็นใด

## 3. แผนการดำเนินงานและไฟล์เป้าหมาย (Implementation Breakdown)

### 3.1 สไตล์ชีต CSS (Styling & Design Tokens)
- **ไฟล์:** `HRCP-KKU-Academic/src/main/resources/static/css/esign.css`
- **การเพิ่มคลาสสไตล์ใหม่:**
  1. `.sig-choice-card`: การ์ดแสดงลายเซ็นที่สวยงาม มีการเปลี่ยนผ่านนุ่มนวล (Smooth transition), Hover effect ยกการ์ดขึ้นเล็กน้อย
  2. `.sig-choice-radio-indicator`: วงกลม Radio จำลองแบบโมเดิร์น เมื่อถูกเลือกจะกลายเป็นสีน้ำเงินพร้อมไอคอนติ๊กถูกสีขาว
  3. `.btn-check:checked + .sig-choice-card`: กำหนดกรอบสีน้ำเงิน `2px solid #0d6efd`, พื้นหลังสีฟ้าอ่อน `background: #f0f7ff`, เงา `box-shadow: 0 0 0 3px rgba(13,110,253,0.18)`
  4. `.sig-badge-selected`: ป้าย Badge แสดงเฉพาะตอนการ์ดถูกติ๊กเลือก (`display: inline-flex`)
  5. `.sig-choice-preview`: กล่องกรอบรูปภาพลายเซ็นสีขาวคมชัด ไม่กลืนไปกับพื้นหลัง

### 3.2 ปรับปรุงหน้าจอลงนาม (Sign Template)
- **ไฟล์:** `HRCP-KKU-Academic/src/main/resources/templates/academic/esign/sign.html`
- **การเปลี่ยนแปลง:**
  1. ปรับปรุงหัวการ์ดจาก `<i class="fas fa-signature"></i> เลือกลายเซ็น` ให้มีคำอธิบายชัดเจนว่า *"เลือกลายเซ็นที่ต้องการประทับลงในเอกสาร"*
  2. ปรับการ์ดวนลูป `mySignatures` ให้ใช้โครงสร้าง `.sig-choice-card`
  3. แสดงป้าย **"ลายเซ็นหลัก"** สำหรับลายเซ็นที่ `sig.isDefault`
  4. แสดงป้าย **"กำลังเลือกใช้อันนี้"** และไอคอน Checkmark อย่างโดดเด่น
  5. เพิ่มกล่องแจ้งเตือนสรุปสถานะการเลือกปัจจุบัน (Live Selected Status Box)
  6. เพิ่ม JavaScript Event Listener ให้สลับป้ายข้อความสรุป และไฮไลท์การ์ดทันทีเมื่อผู้ใช้คลิกเลือกลายเซ็นต่าง ๆ รวมถึงส่ง Signal โหลดตัวอย่าง PDF ใหม่แบบอัตโนมัติ

### 3.3 ตรวจสอบความสอดคล้องในจุดอื่น ๆ
- ตรวจสอบ `_signature_panel.html` เพื่อยืนยันว่าขั้นตอนที่ผู้ใช้ต้องลงนาม (My Pending Step) มีป้ายบอกและปุ่มกดที่ชัดเจนเช่นเดียวกัน

## 4. ประเด็นสำหรับให้ผู้ใช้ยืนยัน (Socratic Gate / Design Decisions)

> [!IMPORTANT]
> **ประเด็นที่ 1: รูปแบบการจัดวางการ์ดลายเซ็น (Layout Options)**
> - **แบบ A (แนะนำ):** แสดงเป็นการ์ดเรียงแนวตั้งแบบเต็มความกว้าง (Full-width Stacked Cards) มีข้อมูลชื่อลายเซ็น, ป้ายสถานะ, รูปตัวอย่างลายเซ็นขนาดใหญ่ชัดเจน พร้อมปุ่ม Radio ด้านซ้าย
> - **แบบ B:** แสดงเป็นการ์ดตาราง 2 คอลัมน์ (Grid 2 Columns) เหมือนเดิม แต่ปรับกรอบให้เด่นชัด มีขอบสีน้ำเงิน ป้าย Checkmark และแถบสรุปด้านล่าง

> [!NOTE]
> **ประเด็นที่ 2: ข้อความกำกับบริบทการลงนาม (Contextual Confirmation)**
> - ต้องการให้มีกล่องสรุปด้านล่างการ์ด เช่น *"✍️ ระบบจะประทับลายเซ็นนี้ในตำแหน่ง: [ตำแหน่งของคุณ]"* หรือไม่ เพื่อให้ผู้ใช้มั่นใจ 100% ก่อนกดยืนยันลงนาม?

## 5. แผนการทดสอบและตรวจสอบ (Verification Plan)

### 1. Manual Visual Verification
- เปิดหน้าลงนามเอกสาร (`/esign/sign/{id}`)
- ตรวจสอบว่าลายเซ็นที่ถูกเลือกเริ่มต้น (Default) มีกรอบสีน้ำเงิน ป้ายติ๊กถูก และแถบสรุปชัดเจน
- ทดลองคลิกสลับเลือกลายเซ็นอื่น -> สังเกตว่ากรอบ ป้ายสถานะ และแถบสรุปสลับตำแหน่งทันทีอย่างนุ่มนวล
- ตรวจสอบการแสดงผลบนอุปกรณ์หน้าจอแคบ (Mobile / Tablet) ว่าการ์ดไม่บีบอัดจนดูลายเซ็นไม่ออก

### 2. Automated Tests
- รันชุดทดสอบความถูกต้องของระบบ E-Signature ทั้งหมด:
  `./mvnw test -Dtest=SigningControllerTest,SigningWorkflowTest`
- ตรวจสอบว่าการส่ง `userSignatureId` ไปยัง Backend ยังคงทำงานถูกต้อง 100%
