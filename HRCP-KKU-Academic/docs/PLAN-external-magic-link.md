# แผน: ลิงก์เข้าสู่ระบบทางอีเมลสำหรับผู้ลงนามภายนอก มข. (Magic Link)

**รหัสเอกสาร:** `docs/PLAN-external-magic-link.md`
**สถานะ:** ทำแล้วครบ 14 ต.ค. 2569 — E2E: `ExternalSignerMagicLinkBrowserTest`
**ที่มา:** `PLAN-external-signer.md` ข้อ 2 ขั้นที่ 3 (แผนนี้ใช้แทน "ตั้งรหัสผ่าน + OTP")
**วันที่:** 14 ต.ค. 2569

---

## 1. โจทย์

ระบบสร้างบัญชี `ROLE_EXTERNAL` ให้ผู้ลงนามภายนอกได้แล้ว (`ExternalSignerService`) และลงนามแบบไม่มี Digital ID ได้แล้ว (OTP ทางอีเมล + `SystemSealService`)
**แต่เข้าสู่ระบบไม่ได้** เพราะบัญชีนี้เข้าได้ทาง KKU SSO เท่านั้น รหัสผ่านเป็นค่าสุ่มที่ไม่มีใครรู้ และ form login ถูกปิดในโหมด SSO

คนนอก มข. ไม่มีบัญชี KKU SSO จึงลงนามไม่ได้ คำร้องจึงติดอยู่ที่ขั้นของคนนั้น
อีเมลเชิญใน `ExternalSignerService.invitationBody` ยังบอกให้ "เข้าสู่ระบบด้วย KKU SSO" ซึ่งคนนอกทำไม่ได้

## 2. หลักการ

1. **เฉพาะคนนอก มข. เท่านั้น** ลิงก์นี้ใช้ได้กับบัญชี `ROLE_EXTERNAL` ที่อีเมลไม่ใช่โดเมนของ มข. (ข้อ 2.1) ส่วนบัญชีอื่น รวมถึงบุคลากร มข. จากคณะอื่น ยังต้องเข้าทาง KKU SSO เหมือนเดิม
2. **ไม่มีรหัสผ่าน** คนนอกส่วนใหญ่ลงนามครั้งเดียว รหัสผ่านจึงเป็นภาระมากกว่าประโยชน์ และ form login ต้องปิดต่อไป
3. **ใช้ทางเดิมทั้งหมดหลังเข้าระบบ** ได้แก่ `SignInService.completeSignIn` กฎ `externalUserPaths()` หน้าลงนาม OTP และระบบประทับรับรอง ไม่สร้างทางลงนามคู่ขนาน
4. **ลิงก์ใช้ได้ครั้งเดียว มีอายุ และเก็บเฉพาะค่า hash** ถ้าฐานข้อมูลรั่ว ก็ไม่มีลิงก์ที่ใช้ได้หลุดออกไป

### 2.1 จำแนกผู้ลงนามจากอีเมล: นอกวิทยาลัย กับ นอกมหาวิทยาลัย

`ROLE_EXTERNAL` หมายถึง "ไม่อยู่ในทะเบียนบุคลากรของวิทยาลัย (`FsFaculty`)" ซึ่งรวมคนสองกลุ่มที่ต่างกันมาก:

| กลุ่ม | ดูจาก | บทบาท | เข้าสู่ระบบ | ขอ .p12 จาก | ข้อความแนะนำ |
| --- | --- | --- | --- | --- | --- |
| **ในวิทยาลัย** | อยู่ใน `FsFaculty` | `ROLE_USER` | KKU SSO | i.kku.ac.th | ฉบับ มข. (เดิม) |
| **นอกวิทยาลัย แต่ใน มข.** (คณะ/หน่วยงานอื่น) | `ROLE_EXTERNAL` + อีเมลโดเมน มข. | `ROLE_EXTERNAL` | **KKU SSO** (`SsoAccessPolicy` รับบัญชีนี้อยู่แล้ว) | **i.kku.ac.th** | **ฉบับ มข.** |
| **นอก มข.** | `ROLE_EXTERNAL` + อีเมลโดเมนอื่น | `ROLE_EXTERNAL` | **magic link** (แผนนี้) | หน่วยงานต้นสังกัด (ไม่บังคับ) | ฉบับคนนอก (ข้อ 4.10) |

กลุ่มที่สองมีบัญชี KKU SSO และขอ .p12 ของ มข. ได้ จึง **ไม่ควร** ได้ magic link และ **ไม่ควร** เห็นคู่มือคนนอก

**ตราระบบใช้ได้เฉพาะคนนอก มข.** (ตัดสินแล้ว 14 ต.ค. 2569) บุคลากร มข. ทุกคน รวมถึงคณะอื่นที่เป็น `ROLE_EXTERNAL` ต้องลงนามด้วย .p12 ของ มข. เท่านั้น เพราะทุกคนมีสิทธิ์ขอได้ที่ i.kku.ac.th ดูข้อ 4.9
ทุกจุดในแผนนี้ที่พูดถึง "คนนอก" หมายถึงกลุ่มที่สามเท่านั้น และต้องเช็กด้วย `KkuEmailDomains.isOutsideKku(user)` ไม่ใช่ `user.isExternal()`

**วิธีจำแนก:**

- เพิ่ม config `app.kku.email-domains=kku.ac.th,kkumail.com` (คั่นด้วยจุลภาค) ให้ตรงกับโดเมนที่ KKU SSO ส่งมา คือ `kku.ac.th` (บุคลากร) และ `kkumail.com` (บัญชี KKU อีกโดเมน เช่น บัญชีผู้ดูแลระบบใน `AdminInitializer` — ผู้ใช้ระบบนี้เป็นบุคลากร ไม่ใช่นักศึกษา) และคลาส `KkuEmailDomains` ที่มี `isKku(email)` ซึ่งตรงทั้งโดเมนเต็มและ subdomain เช่น `x@kku.ac.th`, `x@en.kku.ac.th` แต่ไม่ตรง `x@notkku.ac.th`
- `KkuEmailDomains` เป็น Spring bean มีเมธอด `isOutsideKku(UserDtls)` = `user.isExternal() && !isKku(user.getEmail())` ไม่ใส่ใน entity `UserDtls` เพราะ entity อ่าน config ไม่ได้
- ใช้ใน `ExternalLinkService`, `SignatureNotifier` และ `ExternalSignerService` ส่วนเทมเพลตใช้ model attribute `outsideKku` ที่ `GlobalModelAdvice` ใส่ให้ทุกหน้า
- ดูจากอีเมลตอนใช้งานทุกครั้ง ไม่เก็บเป็นคอลัมน์ ถ้าแก้อีเมลของบัญชี กลุ่มจะเปลี่ยนตามทันที และไม่ต้องย้ายข้อมูล

**กรณีขอบ:**

- **บุคลากร มข. ที่ถูกเชิญด้วยอีเมลส่วนตัว** (เช่น gmail) จะถูกนับเป็นนอก มข. ได้ magic link และลงนามด้วยตราระบบได้ ไม่เสียหาย แต่ไม่ตรงกับความจริง ฟอร์มเชิญจึงต้องมีคำแนะนำว่า "บุคลากร มข. กรุณาใช้อีเมล @kku.ac.th"
- **คนนอกที่มีอีเมล @kku.ac.th** (เช่น อาจารย์พิเศษที่ได้บัญชี มข.) จะเข้าทาง SSO ได้ จึงถือเป็นกลุ่มที่สอง และควรเป็นกลุ่มนั้นจริง
- **อีเมล `kkumail.com`** อยู่ในค่าเริ่มต้น เพราะเจ้าของอีเมลนี้เข้าทาง KKU SSO ได้ จึงเป็นกลุ่มที่สอง ถ้าไม่ใส่ คนกลุ่มนี้จะได้ magic link ทั้งที่มี SSO
- **โดเมนย่อยของหน่วยงาน** (เช่น `computing.kku.ac.th`, `en.kku.ac.th`) ตรงกับ `kku.ac.th` แบบ subdomain อยู่แล้ว แต่ระบบจับคู่บัญชีด้วยอีเมลที่ SSO ส่งมา ซึ่งน่าจะเป็นอีเมลหลัก `@kku.ac.th` (ยังไม่ได้ยืนยัน) ถ้าเชิญด้วยอีเมลย่อย บัญชีที่สร้างอาจไม่ตรงกับอีเมลที่ SSO ส่งมา และเข้าระบบไม่ได้ ฟอร์มเชิญจึงต้องแนะนำให้ใช้อีเมลหลัก `@kku.ac.th` ของบุคลากร
- **ก่อน deploy** ให้ดูใน log ของ production ว่าบรรทัด `SSO access check for ...` มีโดเมนอื่นนอกจากสองโดเมนนี้หรือไม่ ถ้ามี ให้เพิ่มใน config ได้โดยไม่ต้องแก้โค้ด

## 3. Flow

```
อีเมล "ขอความอนุเคราะห์ลงนาม" (ถึงคนนอก)
   └─ ปุ่ม: https://hrd.../auth/link/{token}
        │
        ▼
GET /auth/link/{token}      แสดงหน้า "ยืนยันเข้าสู่ระบบ" (ไม่ใช้ token)
        │  ผู้ใช้กดปุ่ม
        ▼
POST /auth/link/{token}     ตรวจ token → ใช้ token → completeSignIn(EMAIL_LINK)
        │
        ▼
/esign/sign/{stepId}        หน้าลงนามเดิม: .p12 ของตัวเอง หรือ OTP + ตราระบบ
```

**ทำไม GET ไม่ใช้ token ทันที:** ระบบอีเมลของหน่วยงาน (Microsoft Defender Safe Links, Proofpoint, Mimecast) เปิดลิงก์ในอีเมลล่วงหน้าเพื่อสแกน
ถ้า GET ใช้ token ไปเลย ลิงก์จะหมดก่อนผู้ลงนามได้กด ลิงก์ใช้ครั้งเดียวจะพังเพราะเรื่องนี้บ่อยที่สุด จึงต้องให้ผู้ใช้กดปุ่ม (POST + CSRF) ก่อน

**ขอลิงก์ใหม่:** `GET/POST /auth/link` กรอกอีเมลแล้วระบบส่งลิงก์ใหม่
ระบบตรวจอีเมลกับบัญชีในระบบแล้วบอกผลตรง ๆ (เปลี่ยนตามที่ผู้ใช้ขอ 14 ต.ค. 2569): ส่งแล้ว (เขียว) / เพิ่งส่งไป /
อีเมล มข. ให้ใช้ KKU SSO / ไม่ใช่บัญชีผู้ลงนามภายนอก / บัญชีถูกปิด / ไม่พบอีเมลนี้ (แดง)
แลกกับการที่หน้านี้บอกได้ว่าอีเมลไหนเป็นผู้ลงนามภายนอก — จำกัดด้วย RateLimitFilter (30 ครั้งต่อนาทีต่อ IP)

### 4.2 Token

- สุ่ม 32 ไบต์ด้วย `SecureRandom` แล้วเข้ารหัสเป็น base64url ไม่มี padding (43 ตัวอักษร)
- เก็บเฉพาะ `sha256(token)` ค้นด้วย hash จึงไม่ต้องเปรียบเทียบแบบ constant-time
- อายุ 7 วัน (`app.auth.email-link.ttl-days=7`) ซึ่งตรงกับรอบเตือนลงนาม
- ใช้ครั้งเดียว: `UPDATE ... SET used_at = now() WHERE id = ? AND used_at IS NULL` แล้วตรวจว่ามีแถวถูกแก้ 1 แถว เพื่อกันกรณีกดสองครั้งพร้อมกัน

### 4.4 เงื่อนไขของ `redeem` (ต้องผ่านทุกข้อ)

1. พบ hash, `used_at IS NULL` และ `expires_at > now()`
2. `isOutsideKku(user)` เป็นจริง ตรวจซ้ำตอนใช้ เพราะบัญชีอาจถูกเปลี่ยนบทบาทหลังออกลิงก์
3. `signInService.isLocallyUsable(user)` เป็นจริง (แอดมินปิดบัญชีแล้วต้องเข้าไม่ได้)

ถ้าไม่ผ่าน ให้แสดงข้อความเดียว "ลิงก์นี้หมดอายุหรือถูกใช้แล้ว" พร้อมปุ่มขอลิงก์ใหม่ และ log เหตุผลจริงฝั่งเซิร์ฟเวอร์

ถ้าผ่าน:
- เรียก `completeSignIn(request, response, user, Method.EMAIL_LINK, null)` ซึ่งหมุน session id และบันทึก `recordSignIn` ให้อยู่แล้ว
- `session.setMaxInactiveInterval(30 * 60)` ให้ session คนนอกสั้นกว่าปกติ
- redirect ไป `/esign/sign/{stepId}` ถ้ามี step ไม่เช่นนั้นไป `landingPageFor(user)` (`/esign/inbox`)
- ไม่เรียก `startTwoFactor` เพราะลิงก์มาทางอีเมลอยู่แล้ว OTP ทางอีเมลอีกรอบจึงเป็นช่องทางเดียวกันซ้ำ

### 4.5 กันไม่ให้ลิงก์กลายเป็นทางเลี่ยง SSO

- เชิญด้วยอีเมลโดเมน มข. ยังทำได้เหมือนเดิม และได้บัญชี `ROLE_EXTERNAL` ที่เข้าทาง KKU SSO (กลุ่มที่สองในข้อ 2.1) **ไม่ปฏิเสธ** เพราะบุคลากรคณะอื่นไม่อยู่ใน `FsFaculty` จึงเลือกจากรายชื่อไม่ได้
- `issue()` และ `redeem()` ปฏิเสธบัญชีที่ไม่ใช่ `isOutsideKku` ทั้งคู่ ทำให้ magic link ไปถึงคน มข. ไม่ได้ แม้ notifier มีบั๊ก
- `SignatureNotifier` เลือกลิงก์ตาม `isOutsideKku` ผู้ลงนามกลุ่มที่สองได้ `/esign/sign/{id}` เหมือนคนในวิทยาลัย แล้วเข้าทาง SSO

### 4.6 อีเมล

- **เชิญ** (`invitationBody`) แยกตามกลุ่มในข้อ 2.1:
  - **นอกวิทยาลัยแต่ใน มข.**: คงบรรทัด "เข้าสู่ระบบด้วย KKU SSO" ไว้ แต่เปลี่ยนบรรทัด Digital ID เป็น "ท่านต้องลงนามด้วย Digital ID (.p12) ของ มข. กรุณาดาวน์โหลดจาก i.kku.ac.th แล้วติดตั้งที่เมนู ‘ลายเซ็นของฉัน’ ก่อนถึงลำดับลงนาม" และตัดข้อความ "หากไม่มี ระบบจะส่งรหัสยืนยันตัวตนไปยังอีเมลนี้" ออก เพราะกลุ่มนี้ใช้ตราระบบไม่ได้แล้ว
  - **นอก มข.**: เปลี่ยนเป็น "เมื่อถึงลำดับการลงนาม ระบบจะส่งอีเมลพร้อมปุ่มเข้าสู่ระบบ ไม่ต้องตั้งรหัสผ่าน ปุ่มใช้ได้ครั้งเดียวภายใน 7 วัน หากหมดอายุขอใหม่ได้ที่ {base}/auth/link" และ "ไม่จำเป็นต้องมี Digital ID"
- **ขอให้ลงนาม / เตือน / ถึงกำหนด** (เฉพาะนอก มข.): ปุ่ม "เข้าสู่ระบบเพื่อลงนาม" ชี้ไปที่ลิงก์ใหม่ และมีบรรทัดเล็กใต้ปุ่มว่า "ลิงก์นี้ใช้ได้ครั้งเดียว โปรดอย่าส่งต่ออีเมลฉบับนี้"
- อีเมลแต่ละฉบับออกลิงก์ใหม่ ลิงก์เก่าที่ยังไม่ใช้ยังใช้ได้จนหมดอายุ (ไม่ยกเลิกลิงก์เก่า เพราะผู้ใช้อาจกดจากฉบับไหนก็ได้)
- บัญชีทดสอบ (`EmailTemplateHelper.isTestEmail`) ยังออก token ได้ แต่ไม่ส่งเมล และ log URL ระดับ DEBUG ไว้ใช้ทดสอบ e2e

### 4.7 Audit

- `recordSignIn` บันทึกวิธีเข้าเป็น "ลิงก์ทางอีเมล"

### 4.9 ทางเลือกของผู้ลงนาม: มี .p12 ก็ใช้ของตัวเอง ไม่มีก็ยืนยันทางอีเมล

เฉพาะ **คนนอก มข.** ที่ไม่ถูกบังคับให้มี Digital ID ระบบเลือกให้ตามสถานะของแต่ละคน:

| สถานะของผู้ลงนาม | วิธีลงนาม | ใบรับรองในไฟล์ PDF |
| --- | --- | --- |
| ติดตั้ง .p12 ที่ยังไม่หมดอายุแล้ว | กรอก PIN ของ .p12 | ของผู้ลงนามเอง (หลักฐานหนักสุด) |
| คนนอก มข. ที่ไม่มี .p12 หรือ .p12 หมดอายุ | กรอกรหัส OTP ทางอีเมล | ตราระบบ โดยเหตุผลระบุชื่อและอีเมลของผู้ลงนาม |
| บุคลากร มข. (ทั้งในวิทยาลัยและคณะอื่น) ที่ไม่มี .p12 หรือ .p12 หมดอายุ | **ลงนามไม่ได้** จนกว่าจะติดตั้ง .p12 จาก i.kku.ac.th | — |

**ต้องแก้: จำกัดตราระบบให้เฉพาะคนนอก มข.**

- `SystemSealService.availableFor(signer)` เปลี่ยนจาก `signer.isExternal() && isConfigured()` เป็น `kkuEmailDomains.isOutsideKku(signer) && isConfigured()` จุดเดียวนี้คุมทั้ง `sign()`, `sendSigningOtp()` และ `sealAvailable` ในหน้าลงนาม
- เพิ่ม `KkuEmailDomains` ใน constructor ของ `SystemSealService` และแก้ constructor แบบ package-private ที่ `SystemSealServiceTest` ใช้ตาม
- บุคลากร มข. คณะอื่นที่ไม่มี .p12 จะเห็นกล่องแดง "จำเป็นต้องติดตั้ง Digital ID (.p12)" พร้อมคู่มือ i.kku.ac.th ที่มีอยู่แล้วใน `sign.html` (เงื่อนไข `!sealAvailable`) ไม่ต้องสร้างหน้าใหม่
- อีเมลเชิญของกลุ่มนี้ (ข้อ 4.6) ต้องบอกตั้งแต่แรกว่า "กรุณาติดตั้ง Digital ID (.p12) ของ มข. จาก i.kku.ac.th ก่อนถึงลำดับลงนาม" ไม่อย่างนั้นจะมารู้ตอนถึงคิว และคำร้องจะช้า
- **ก่อน deploy:** หาขั้นลงนามที่ยังเปิดอยู่ของ `ROLE_EXTERNAL` ที่ใช้อีเมลโดเมน มข. และยังไม่มี .p12 ถ้ามี ให้แจ้งเจ้าของขั้นนั้นให้ติดตั้ง .p12 ก่อน เพราะหลัง deploy เขาจะใช้ตราระบบไม่ได้แล้ว

**สิ่งที่โค้ดทำอยู่แล้ว (ไม่ต้องแก้):**

- `SignatureWorkflowService.sign` ใช้ .p12 ก่อนถ้ามีและยังไม่หมดอายุ ถ้าไม่มีหรือหมดอายุก็ใช้ตราระบบ เมื่อ `availableFor` อนุญาต (บรรทัด ~1015)
- `/esign/my-certificates/upload` รับ .p12 ของ CA ใดก็ได้ ไม่จำกัดเฉพาะ มข. คนที่มี Digital ID ของหน่วยงานตัวเองจึงติดตั้งได้
- ผู้ลงนามติดตั้ง .p12 เพิ่มได้ทุกเมื่อ ครั้งถัดไปที่ลงนามระบบจะใช้ใบรับรองนั้นเอง

**สิ่งที่ต้องแก้ เพื่อให้ผู้ลงนามเห็นว่ามีทางเลือก:**

1. **หน้าลงนาม (`esign/sign.html` การ์ด `sealAvailable`)** ตอนนี้ทางที่ใช้ .p12 ซ่อนอยู่ใน tooltip ให้แสดงสองทางชัด ๆ:
   - "ยืนยันตัวตนทางอีเมล (ไม่ต้องติดตั้งอะไร)" แสดงเป็นทางหลัก
   - "มี Digital ID ของหน่วยงาน? ติดตั้ง .p12 แล้วลงนามด้วยใบรับรองของท่านเอง" แสดงเป็นลิงก์รองไปที่ `/esign/my-signatures`
2. **ข้อความแนะนำเรื่อง .p12 ต้องเปลี่ยนตามว่าเป็นคนนอกหรือคนใน** ดูข้อ 4.10
3. **อีเมลเชิญและอีเมลขอให้ลงนาม** บอกทั้งสองทางในบรรทัดเดียว: "ไม่จำเป็นต้องมี Digital ID หากท่านมีของหน่วยงาน สามารถติดตั้งเพื่อใช้ลงนามแทนได้"
4. **ต้องมีลายเซ็นก่อน** ตอนนี้ถ้ายังไม่มีลายเซ็นที่บันทึกไว้ หน้าลงนามจะให้ไปสร้างที่ `/esign/my-signatures` ก่อน ซึ่งคนนอกจะต้องออกจากหน้าลงนามหนึ่งรอบ
   - ในแผนนี้: เปลี่ยนข้อความให้ชัดว่า "วาดหรืออัปโหลดลายเซ็น แล้วระบบจะพากลับมาที่เอกสารนี้" และส่ง `?return=/esign/sign/{id}` ไปด้วย
   - นอกขอบเขต: ให้วาดลายเซ็นได้ในหน้าลงนามเลย

**ขั้นตอนของทางที่ไม่มี .p12 (โค้ดมีอยู่แล้ว):**

1. หน้าลงนามเห็นว่าไม่มีใบรับรอง (หรือใบรับรองหมดอายุ) และ `SystemSealService.availableFor(user)` เป็นจริง จึงแสดงปุ่ม "ส่งรหัสยืนยันทางอีเมล" (`POST /esign/sign/{id}/email-otp`)
2. ผู้ลงนามกรอก OTP แล้ว `SignatureWorkflowService.sign(..., emailOtp)` ตรวจรหัส
3. ระบบประทับลงไฟล์ด้วย `secrets/system-seal.p12` โดยเหตุผลในลายเซ็นระบุชื่อ อีเมล และเวลาของผู้ลงนาม (`SystemSealService.reasonFor`)

**ช่องโหว่ที่ต้องปิดในแผนนี้:**

- **OTP ตอนลงนามไม่จำกัดจำนวนครั้งที่กรอกผิด** รหัสมี 8 หลักและอายุ 5 นาที (`TwoFactorService`) แต่ `sign()` ไม่นับครั้งที่ผิด ต่างจาก OTP ตอนเข้าสู่ระบบที่นับ ให้ล้างรหัสทิ้งเมื่อกรอกผิดครบ 5 ครั้ง แล้วให้ขอรหัสใหม่
- **ปุ่ม "ส่งรหัส" ไม่มีระยะรอ** กดรัว ๆ ได้ อีเมลจะท่วมกล่องของผู้ลงนาม ให้รอ 60 วินาทีก่อนส่งใหม่ (ใช้ค่า `resend-cooldown-seconds` เดียวกับข้อ 5)

- **ไม่มีไฟล์ตราระบบก็ลงนามไม่ได้เลย** `deploy.yml` สร้างไฟล์ให้ครั้งแรกที่ deploy แต่ขั้นนั้นตั้ง `continue-on-error: true` ถ้า keytool ล้มเหลว deploy จะยังผ่าน และผู้ลงนามภายนอกที่ไม่มี .p12 จะติดค้างโดยไม่มีใครรู้
  - ก่อนเปิดใช้: ตรวจบน production ว่ามี `secrets/system-seal.p12` และ log ตอนสตาร์ตขึ้น `System seal certificate: ...`
  - ตอนเลือกผู้ลงนามภายนอก (`PeopleApiController` / `ExternalSignerService.invite`): ถ้า `!systemSeal.isConfigured()` ให้เตือนผู้เชิญว่า "ผู้ลงนามต้องมี Digital ID ของตัวเอง" แต่ไม่ต้องบล็อก
  - หน้าลงนามของคนนอกที่ไม่มี .p12 และตราระบบยังไม่พร้อม: แสดงข้อความให้ติดต่อเจ้าหน้าที่ แทนปุ่มที่กดไม่ได้ผล
- **ใบรับรองตราระบบเป็นแบบ self-signed** (`keytool -genkeypair`, `CN=HRCP e-Signature Seal`) Adobe และ Foxit จะขึ้นว่า "ไม่ทราบความถูกต้องของลายเซ็น" จนกว่าเครื่องที่ตรวจเอกสารจะติดตั้ง `system-seal.cer` เป็นใบรับรองที่เชื่อถือ
  - ระยะสั้น: แจก `system-seal.cer` ให้เจ้าหน้าที่ที่ตรวจเอกสาร และแนบวิธีติดตั้งไว้ในหน้า `/esign/verify`
  - ระยะยาว (นอกขอบเขต): ขอใบรับรองของหน่วยงานจากผู้ดูแล Digital ID ของ มข. หรือ CA ที่ Adobe เชื่อถือ (AATL) แล้วเปลี่ยนไฟล์ ไม่ต้องแก้โค้ด

**เทสเพิ่ม:**

- คนนอกที่มี .p12 ของ CA อื่น (ไม่ใช่ มข.) ติดตั้งแล้วลงนาม PDF ต้องมีใบรับรองของเขาเอง ไม่ใช่ตราระบบ
- คนนอกที่ .p12 หมดอายุ ต้องเห็นการ์ดยืนยันทางอีเมล และลงนามด้วยตราระบบได้
- เปิด `/esign/sign/{id}` และ `/esign/my-signatures` ในฐานะคนนอก (ทั้งกรณีไม่มี .p12 และกรณี .p12 หมดอายุ) HTML ต้องไม่มี `i.kku.ac.th`, `KKU SSO`, `KKU Mail` หรือ "ของมหาวิทยาลัยขอนแก่น" และต้องมีคำว่า "ไม่บังคับ"
- เปิดหน้าเดียวกันในฐานะคนใน ข้อความต้องเหมือนเดิม
- คนนอกที่ไม่มี .p12 เข้าด้วย magic link แล้วขอ OTP แล้วลงนาม PDF ที่ได้ต้องมีลายเซ็นของตราระบบ และเหตุผลมีอีเมลของผู้ลงนาม
- ถ้าตราระบบไม่พร้อม หน้าลงนามต้องแสดงข้อความให้ติดต่อเจ้าหน้าที่ ไม่ใช่ error 500
- `availableFor`: `ROLE_EXTERNAL` ที่อีเมลนอก มข. เป็นจริง ส่วน `ROLE_EXTERNAL` ที่เป็น `@kku.ac.th` หรือ `@kkumail.com` และ `ROLE_USER` เป็นเท็จ
- `ROLE_EXTERNAL` ที่เป็น `@kku.ac.th` และไม่มี .p12: หน้าลงนามต้องไม่มีการ์ด OTP แต่มีกล่องแดงให้ติดตั้ง .p12 และลิงก์ i.kku.ac.th, `POST /email-otp` ต้องได้ "บัญชีนี้ต้องลงนามด้วย Digital ID (.p12)" และ `POST /sign` ที่แนบ `emailOtp` มาต้องไม่ผ่าน
- `ROLE_EXTERNAL` ที่เป็น `@kku.ac.th` และมี .p12 ยังลงนามได้ตามปกติ
- กรอก OTP ผิด 5 ครั้งแล้ว รหัสที่ถูกต้องก็ต้องใช้ไม่ได้ ต้องขอรหัสใหม่
- กด "ส่งรหัส" ซ้ำภายใน 60 วินาที ต้องไม่มีอีเมลฉบับที่สองออกไป

### 4.10 ข้อความแนะนำ .p12 สำหรับคนนอก

ข้อความเรื่อง .p12 ทุกจุดตอนนี้เขียนสำหรับบุคลากร มข. เช่น "ดาวน์โหลดจาก i.kku.ac.th" "ใบรับรองของมหาวิทยาลัยขอนแก่น" "รหัสที่แจ้งทาง KKU Mail"
คนนอกขอ .p12 จากระบบของ มข. ไม่ได้ ต้องขอจากหน่วยงานต้นสังกัดของตัวเอง ข้อความจึงต้องแยกตาม `${outsideKku}` (ข้อ 2.1) ไม่ใช่ `user.external` เพราะบุคลากร มข. จากคณะอื่นก็เป็น `ROLE_EXTERNAL` แต่ต้องเห็นคู่มือฉบับ มข. (i.kku.ac.th) เหมือนเดิม

**หลักของข้อความสำหรับคนนอก:**

- บอกก่อนว่า **ไม่บังคับ** ไม่มี .p12 ก็ลงนามได้ด้วยการยืนยันทางอีเมล
- บอกว่า **ขอได้จากที่ไหน**: ฝ่ายเทคโนโลยีสารสนเทศหรือฝ่ายบุคคลของหน่วยงานต้นสังกัด หรือผู้ให้บริการออกใบรับรองที่ได้รับอนุญาต (ดูรายชื่อที่ ETDA)
- บอกว่า **ต้องใช้ไฟล์แบบไหน**: ไฟล์ .p12 หรือ .pfx ที่มีกุญแจส่วนตัว และรหัสผ่านของไฟล์ ไฟล์ .cer หรือ .crt ใช้ไม่ได้
- ไม่พูดถึง i.kku.ac.th, KKU Mail หรือ KKU SSO

1. **ไม่บังคับ** ถ้าไม่มี Digital ID ท่านลงนามได้โดยยืนยันรหัสที่ส่งไปทางอีเมล และวิทยาลัยฯ จะรับรองลายมือชื่อในไฟล์ พร้อมระบุชื่อและอีเมลของท่าน
2. **ถ้าต้องการลงนามด้วยใบรับรองของท่านเอง** ให้ขอใบรับรองดิจิทัลส่วนบุคคลจากฝ่ายเทคโนโลยีสารสนเทศหรือฝ่ายบุคคลของหน่วยงานต้นสังกัด หรือจากผู้ให้บริการออกใบรับรองที่ได้รับอนุญาต
3. **ไฟล์ที่ใช้ได้** คือ .p12 หรือ .pfx ที่มีกุญแจส่วนตัว และมีชื่อของท่านในใบรับรอง ส่วนไฟล์ .cer หรือ .crt ใช้ไม่ได้
4. **รหัสผ่าน** คือรหัสของไฟล์ที่ตั้งตอนดาวน์โหลดหรือที่หน่วยงานแจ้ง ไม่ใช่รหัสผ่านอีเมล
5. **การเก็บรักษา** ระบบเข้ารหัสไฟล์ก่อนเก็บ และใช้เฉพาะตอนท่านกดลงนาม ท่านลบออกได้ทุกเมื่อที่หน้านี้

**วิธีทำ:** ใช้ fragment เดิมแต่รับพารามิเตอร์ เช่น `_p12_guide_modal :: modal(${outsideKku})` ไม่แยกเป็นไฟล์ใหม่ เพื่อไม่ให้คู่มือสองฉบับค่อย ๆ เขียนไม่ตรงกัน ข้อความอื่นใช้ `th:if` / `th:unless="${outsideKku}"` คู่กัน

**ทำเพิ่มได้ ถ้าต้องการ:** ตอนติดตั้ง .p12 ถ้าชื่อในใบรับรอง (CN) ไม่ตรงกับชื่อ-สกุลในระบบ ให้เตือนแต่ไม่บล็อก เพราะชื่อภาษาอังกฤษกับภาษาไทยอาจต่างกัน

### 4.11 ไฟล์ใบรับรองแบบอื่นที่คนนอกอาจมี

ระบบลงนามฝั่งเซิร์ฟเวอร์ (`CmsSigner` อ่านเฉพาะ `KeyStore "PKCS12"`) จึงต้องมี **กุญแจส่วนตัว** อยู่ในไฟล์ที่อัปโหลด
ช่องอัปโหลดรับ `.p12` และ `.pfx` อยู่แล้ว ซึ่งเป็นรูปแบบเดียวกัน (PKCS#12)

| สิ่งที่คนนอกอาจมี | ใช้ได้ไหม | ระบบควรทำอย่างไร |
| --- | --- | --- |
| `.p12` / `.pfx` | ได้ | ไม่ต้องแก้ |
| `.cer` / `.crt` / `.der` / `.pem` ที่มีแต่ใบรับรอง | ไม่ได้ เพราะไม่มีกุญแจส่วนตัว | บอกให้ชัดว่า "ไฟล์นี้มีแต่ใบรับรอง ไม่มีกุญแจส่วนตัว กรุณาส่งออกเป็น .p12/.pfx หรือลงนามด้วยการยืนยันทางอีเมล" |
| `.p7b` / `.p7c` (chain) | ไม่ได้ เพราะไม่มีกุญแจส่วนตัว | ข้อความเดียวกับแถวบน |
| `.pem` + `.key` แยกสองไฟล์ | ได้ ถ้ารวมเป็น .p12 ก่อน | ไม่รับในแผนนี้ คู่มือแนะนำให้ฝ่ายไอทีของหน่วยงานแปลงให้ |
| `.jks` / `.keystore` (Java) | ได้ ถ้าแปลงก่อน | ไม่รับในแผนนี้ (พบน้อย) |
| ใบรับรองใน Windows Certificate Store หรือ macOS Keychain | ได้ ถ้าส่งออกพร้อมกุญแจ | คู่มือบอกวิธีส่งออกเป็น .pfx/.p12 สั้น ๆ (ส่งออกได้ก็ต่อเมื่อตอนติดตั้งเปิดให้ export กุญแจไว้) |
| USB token / smart card (เช่น ใบรับรองของหน่วยงานรัฐ) | ไม่ได้ เพราะกุญแจถอดออกจากอุปกรณ์ไม่ได้ | คู่มือบอกตรง ๆ ว่าระบบนี้ใช้ไม่ได้ ให้ลงนามด้วยการยืนยันทางอีเมล |
| ลงนามผ่านระบบคลาวด์ของผู้ให้บริการ (remote signing) | ไม่ได้ เพราะกุญแจอยู่ที่ผู้ให้บริการ | เหมือนแถวบน |

**ปัญหาตอนนี้:** ถ้าอัปโหลดไฟล์ผิดประเภท เช่นเปลี่ยนชื่อ `.cer` เป็น `.p12` ระบบตอบว่า "Digital ID Password ไม่ถูกต้อง หรือไฟล์ .p12 ไม่สมบูรณ์" (`UserDigitalCertificateService` บรรทัด 194 และ 302) ผู้ใช้จะนึกว่ากรอกรหัสผิดแล้วลองซ้ำไปเรื่อย ๆ

**แก้:** ก่อนเปิดด้วย PKCS12 ให้ตรวจเนื้อไฟล์ (ไม่ดูจากนามสกุล) แล้วแยกข้อความ:

1. ขึ้นต้นด้วย `-----BEGIN CERTIFICATE-----` / `-----BEGIN PKCS7-----` หรือ `CertificateFactory.getInstance("X.509")` อ่านได้ → "ไฟล์นี้มีแต่ใบรับรอง ไม่มีกุญแจส่วนตัว ..."
2. ขึ้นต้นด้วย `-----BEGIN` แบบอื่น (เช่น `PRIVATE KEY`) → "ไฟล์ PEM ยังใช้ไม่ได้ กรุณาแปลงเป็น .p12/.pfx"
3. PKCS12 เปิดได้แต่ไม่มี entry ที่มีกุญแจ → "ไฟล์นี้ไม่มีกุญแจส่วนตัว ..."
4. PKCS12 เปิดไม่ได้เพราะรหัสผิด → ข้อความเดิม แต่ตัดส่วน "หรือไฟล์ไม่สมบูรณ์" ออก

ทุกข้อความสำหรับคนนอกให้จบด้วย "หรือลงนามด้วยการยืนยันทางอีเมลได้โดยไม่ต้องติดตั้ง"

**คู่มือฉบับคนนอก (ข้อ 4.10)** เพิ่มข้อ "ไฟล์ที่ใช้ไม่ได้": .cer/.crt/.pem ที่มีแต่ใบรับรอง, USB token/smart card และ remote signing

**เทส:** อัปโหลด .cer (PEM และ DER), .p7b, PEM private key, และ .p12 ที่ไม่มีกุญแจ แต่ละแบบต้องได้ข้อความของตัวเอง ไม่ใช่ข้อความว่า "รหัสผิด"

### 4.12 ทางเข้าของคนนอก มข. เมื่อ production มีแค่ปุ่ม KKU SSO

หน้า `/signin` บน production อยู่ในโหมด SSO (`ssoMode`) มีปุ่มเดียวคือ "เข้าสู่ระบบด้วย KKU SSO" และ form login ถูกปิด (`/login-disabled`)
**คนนอก มข. ไม่ต้องผ่านหน้านี้** ทางเข้าหลักคือปุ่มในอีเมล ซึ่งไปที่ `/auth/link/{token}` โดยตรง และเปิด session ให้เองโดยไม่ผ่าน `/signin` หรือ KKU SSO

| คนนอกมาจากไหน | ไปที่ | ผลลัพธ์ |
| --- | --- | --- |
| กดปุ่มในอีเมล "ขอความอนุเคราะห์ลงนาม" หรืออีเมลเตือน (**ทางหลัก**) | `/auth/link/{token}` | กดยืนยันแล้วเข้าหน้าลงนามทันที |
| ลิงก์หมดอายุหรือถูกใช้ไปแล้ว | `/auth/link/{token}` | ข้อความ "ลิงก์หมดอายุ" + ปุ่ม "ขอลิงก์ใหม่" ไปที่ `/auth/link` |
| พิมพ์ที่อยู่เว็บเอง หรือกดลิงก์เก่า `/esign/...` | ถูกส่งไป `/signin` | เห็นปุ่ม SSO **และทางเข้าสำรอง** (ด้านล่าง) |
| session หมดระหว่างลงนาม (30 นาที) | `/signin?expired=true` | เหมือนแถวบน |
| กดออกจากระบบ | `/signin?logout=true` | เหมือนแถวบน (iframe ปิด session ของ SSO ยังโหลดตามเดิม แต่ไม่มีผลกับคนนอก) |

**ทางเข้าสำรองบน `/signin` (แก้ `login.html`):** ลิงก์ตัวอักษรบรรทัดเดียว ไม่ใช่ปุ่ม (ปรับตามที่ผู้ใช้เลือก 14 ต.ค. 2569)

```
สำหรับบุคลากร มข.
[ 🏛 เข้าสู่ระบบด้วย KKU SSO ]

ผู้ลงนามจากหน่วยงานภายนอก? รับลิงก์เข้าสู่ระบบทางอีเมล   ← ลิงก์ไป /auth/link
```

- แสดงเมื่อ `ssoMode && app.auth.email-link.enabled` ถ้าปิด config ก็ไม่แสดง ทำให้หน้ากลับไปเป็นปุ่มเดียวเหมือนเดิม
- หน้านี้ผู้ใช้เกือบทั้งหมดเป็นบุคลากร มข. ปุ่มหลักจึงเหลือ SSO ปุ่มเดียว
- ถ้าบุคลากร มข. กรอกอีเมล @kku.ac.th ที่ `/auth/link` ระบบไม่ส่งลิงก์ และบอกให้เข้าด้วย KKU SSO
- ถ้าคนนอกกดปุ่ม KKU SSO ผิด เขาจะติดที่หน้า SSO ของมหาวิทยาลัย ซึ่งเราควบคุมไม่ได้ ข้อความใต้ปุ่ม SSO จึงสำคัญ

**`SecurityConfig`:** `/auth/link` และ `/auth/link/**` ต้องเปิด `permitAll` ทั้งในโหมด SSO และโหมดรหัสผ่าน **ห้าม** รวมไว้ใน `passwordLoginPaths()` เพราะชุดนั้นถูกปิดในโหมด SSO

**เทส:**

- `/signin` ในโหมด SSO และเปิด email-link: มีปุ่ม SSO, ข้อความ "สำหรับบุคลากร มข." และลิงก์ไป `/auth/link`
- `/signin` ในโหมด SSO และปิด email-link: มีแค่ปุ่ม SSO เหมือนเดิม
- `/auth/link/**` เข้าได้โดยไม่ล็อกอินในโหมด SSO (ต้องไม่ถูกส่งไป `/signin`)
- คนนอกที่ session หมดแล้วเปิด `/esign/sign/{id}` ถูกส่งไป `/signin` และหน้านั้นมีทางเข้าสำรอง

## 5. Config

```properties
app.auth.email-link.enabled=true
app.auth.email-link.ttl-days=7
app.auth.email-link.session-minutes=30
app.auth.email-link.resend-cooldown-seconds=60
```

ถ้า `enabled=false` ระบบกลับไปใช้ลิงก์เดิม `/esign/sign/{id}` และ `/auth/link/**` ตอบ 404 ใช้เป็นทาง rollback โดยไม่ต้อง deploy ใหม่

- ฐานข้อมูลไม่มีค่า token ดิบ

- หลังเข้าแล้วเปิด `/esign/sign/{stepIdของคนอื่น}` ถูกปฏิเสธ
- `/auth/link` (ขอใหม่) บอกผลตามอีเมล: ส่งแล้ว / เพิ่งส่ง / อีเมล มข. / ไม่ใช่ผู้ลงนามภายนอก / บัญชีถูกปิด / ไม่พบ และส่งเมลเฉพาะกรณีที่ควรส่ง

- `ExternalSignerService.invite` กับอีเมลนอก มข. ได้อีเมลเชิญแบบ magic link

**Notifier**

- ผู้รับในวิทยาลัย และผู้รับ `ROLE_EXTERNAL` ที่เป็นอีเมล มข. ยังได้ `/esign/sign/{id}` เหมือนเดิม

## 10. คำถามก่อนเริ่ม

ตอนลงมือทำ (14 ต.ค. 2569) ใช้คำตอบที่เสนอไว้: เก็บ OTP ตอนลงนาม, ลิงก์อายุ 7 วัน, กดลิงก์หลังลงนามแล้วยังเข้าระบบได้

**สิ่งที่พบระหว่างทำ (ไม่อยู่ในแผนเดิม):**

- หน้า "ลายเซ็นของฉัน" ล็อกการสร้างลายเซ็นไว้จนกว่าจะติดตั้ง .p12 คนนอกที่ไม่มี .p12 จึงลงนามไม่ได้เลยแม้ตราระบบพร้อม แก้ให้ผู้ที่ใช้ตราระบบได้สร้างลายเซ็นได้ทันที และติดตั้ง .p12 ของหน่วยงานเป็นทางเลือก
- `PdfDigitalSignatureService.findKeyAlias` ยอมรับ .p12 ที่ไม่มีกุญแจส่วนตัว ติดตั้งผ่านแต่ลงนามไม่ได้ทีหลัง เพิ่มการตรวจกุญแจตอนติดตั้ง (`CertificateFileKind`)
- ขอลิงก์ใหม่ที่ `/auth/link` ส่งให้คนนอก มข. ทุกบัญชีที่ยังใช้งานได้ ไม่จำกัดเฉพาะคนที่มีขั้นลงนามเปิดอยู่ เพราะกรรมการภายนอกต้องเข้ามาดูเอกสารด้วย ลิงก์พาไปกล่องงานลงนาม
- ระยะรอส่ง OTP ใหม่ผูกกับขั้นลงนามและผู้ลงนาม ไม่ผูกกับผู้ใช้อย่างเดียว
- **ปุ่ม "ส่งรหัสยืนยันทางอีเมล" ใช้ไม่ได้บนเบราว์เซอร์มาตั้งแต่แรก** `esign_consideration.js` ดักทุก submit ของ `#signForm` แล้วเปิดหน้าต่างยืนยันการลงนาม ปุ่มส่งรหัสจึงไม่เคยส่งรหัส E2E จับได้ แก้ให้ปุ่มที่มี `formaction` ผ่านไปตรง ๆ
- ผู้ใช้ระบบไม่มีนักศึกษา ข้อความบนหน้าจอจึงเขียนว่า "บุคลากร มข." เท่านั้น


1. **OTP ตอนลงนาม (ทางที่ไม่มี .p12) จะเก็บไว้ไหม** ตอนนี้คนนอกจะได้อีเมล 2 ฉบับ คือฉบับที่มีลิงก์และฉบับ OTP ซึ่งมาทางเดียวกัน
   ข้อเสนอคือ **เก็บไว้** เพราะ OTP ผูกการกดลงนามกับการยืนยันที่เพิ่งทำไป ได้หลักฐานว่า "ตั้งใจลงนาม ณ เวลานั้น" และโค้ดกับเทสมีอยู่แล้ว
2. **อายุลิงก์ 7 วันพอไหม** หรือให้ตรงกับวันครบกำหนดของขั้นลงนาม (`dueAt`)
3. **ถ้าคนนอกกดลิงก์หลังลงนามขั้นนั้นไปแล้ว** ให้เข้าได้แล้วเห็นสถานะ "ลงนามแล้ว" (ข้อเสนอ) หรือปฏิเสธ
4. **โดเมนของ KKU SSO ครบหรือยัง** ค่าเริ่มต้นคือ `kku.ac.th` (รวม subdomain) และ `kkumail.com` ให้ยืนยันจาก log ของ production หรือสอบถามสำนักเทคโนโลยีดิจิทัลว่ามีโดเมนอื่นอีกไหม
