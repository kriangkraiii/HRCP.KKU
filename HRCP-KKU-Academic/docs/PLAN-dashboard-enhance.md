# Plan: Dashboard Analytics Enhancement — Evaluation Expiry, Yearly Subjects & Essential Metrics

## 📌 Context & Problem
ผู้ใช้งานต้องการเพิ่มมิติข้อมูลเชิงลึกในหน้า **Admin Dashboard Analytics** (`/admin/academic/dashboard`) โดยระบุความต้องการชัดเจน:
1. **ผ่านเมื่อไหร่ (Pass Date & Timeline):** คำร้องผ่านการประเมินเมื่อไหร่ วันที่รับรองผล และระดับผลการประเมิน
2. **เช่นปี 69 มียื่นวิชาไหนบ้าง (Yearly Subject Submissions):** ในปีการศึกษาแต่ละปี (เช่น ปี 2569) มีการยื่นขอรับการประเมินการสอนในรายวิชาใดบ้าง รหัสวิชา/ชื่อวิชา ผู้ยื่น และสถานะผลการประเมิน
3. **แต่ละการประเมินหมดอายุตอนไหนบ้าง (Evaluation Expiration Tracker):** ผลการประเมินการสอนมีอายุ 3 ปีตามเกณฑ์ มข. ต้องสามารถติดตามวันหมดอายุ, นับถอยหลังจำนวนวันที่เหลือ (`daysLeft`), และจัดหมวดหมู่เตือนล่วงหน้า (ใกล้หมดอายุภายใน 90 วัน / หมดอายุแล้ว / ยังใช้ได้)
4. **ข้อมูลที่จำเป็นสำหรับการบริหารงานบุคคลวิชาการ (Essential Academic HR Metrics):** สถิติการขอกำหนดตำแหน่งทางวิชาการ (ผศ./รศ./ศ. และสาขาวิชา), อัตราการผ่านการประเมิน (Pass Rate), และระดับคุณภาพ (ดีเด่น/ดีมาก/ดี)

---

## 🎯 Objectives & Proposed Analytics Features

### 1. ⏱️ Evaluation Expiration & Validity Tracker (ระบบติดตามวันหมดอายุผลประเมิน)
- **KPI Summary Cards:**
  - 🟢 **ผลประเมินที่ยังใช้ได้ (> 90 วัน):** พร้อมนำไปยื่นขอตำแหน่ง
  - 🟡 **ใกล้หมดอายุ (ภายใน 90 วัน / 3 เดือน):** **แจ้งเตือนด่วน!** เพื่อให้เจ้าหน้าที่ HR ติดตามอาจารย์ผู้ยื่นก่อนผลประเมินจะหมดอายุ
  - 🔴 **หมดอายุแล้ว:** ผลประเมินสิ้นผล ไม่สามารถนำไปยื่นขอตำแหน่งได้แล้ว
- **Evaluation Expiry Watchlist Table (ตารางเฝ้าระวังวันหมดอายุ):**
  - รหัสคำร้อง (`KKU-ACAD-2569-xxxx`)
  - ผู้ขอรับการประเมิน (ชื่อ-นามสกุล, ตำแหน่ง)
  - รายวิชาที่ประเมิน (รหัสวิชา - ชื่อวิชา)
  - วันที่ผ่านการประเมิน / วันที่คณะกรรมการรับรอง
  - วันที่หมดอายุ (`evaluationExpiryDate`)
  - ระยะเวลาคงเหลือ (Badge แสดง `เหลือ XX วัน` หรือ `หมดอายุแล้ว`)
  - สถานะการนำไปใช้: ยื่นขอกำหนดตำแหน่งแล้ว หรือ ยังไม่ยื่น (เพื่อให้ HR รู้ว่าต้องตามใคร)

### 2. 📚 Yearly Subject Submissions Analytics (วิเคราะห์รายวิชาที่ยื่นประเมินแยกตามปีการศึกษา)
- **Academic Year Filter (ตัวกรองปีการศึกษา):**
  - เช่น ปีการศึกษา **2569**, **2568**, **2567**, หรือ **ทั้งหมด**
- **Course Submission List & Metrics:**
  - ตารางสรุปรายวิชา: รหัสวิชา, ชื่อวิชา, ภาคการศึกษา/ปีการศึกษา, ผู้ยื่นประเมิน, วันที่ยื่น, สถานะผล (ผ่าน/กำลังดำเนินการ/แก้ไข/ไม่ผ่าน)
  - กราฟ/สรุป Top Subjects: รายวิชาที่มีการยื่นประเมินบ่อยที่สุดในวิทยาลัยฯ

### 3. 🎓 Position Request Pipeline & Majors (สถิติการยื่นขอกำหนดตำแหน่งตามตำแหน่งและสาขาวิชา)
- จำแนกตามตำแหน่งเป้าหมาย: **ผู้ช่วยศาสตราจารย์ (ผศ.)**, **รองศาสตราจารย์ (รศ.)**, **ศาสตราจารย์ (ศ.)**
- จำแนกตามสาขาวิชาหลัก (Major): วิทยาการคอมพิวเตอร์, เทคโนโลยีสารสนเทศ, ภูมิสารสนเทศศาสตร์, ปัญญาประดิษฐ์ ฯลฯ
- จำแนกตามวิธีประเมิน: วิธีปกติ vs วิธีพิเศษ

### 4. 📊 Evaluation Quality & Pass Rate (อัตราความสำเร็จและระดับคุณภาพการสอน)
- **Pass Rate KPI (%):** สัดส่วนคำร้องที่ผ่านเกณฑ์
- **Quality Distribution Chart (Doughnut):** ระดับผลการประเมิน (ดีเด่น, ดีมาก, ดี, ให้แก้ไข, ไม่ผ่าน) ตามเกณฑ์ประกาศ มข. 1607/2566

## 🛠️ Architecture & Task Breakdown

### Phase 1: Backend Data Aggregation (`DashboardAnalyticsService`)
- [ ] สร้าง DTO / Record สำหรับส่งข้อมูลไปยัง View:
  - `EvaluationExpiryItem`: รหัสคำร้อง, ชื่ออาจารย์, รหัสวิชา, ชื่อวิชา, วันที่ผ่าน, วันที่หมดอายุ, จำนวนวันที่เหลือ, สถานะใกล้หมดอายุ/หมดอายุ, สถานะการเชื่อมโยงกับคำร้องขอตำแหน่ง
  - `SubjectSubmissionItem`: ปีการศึกษา, ภาคเรียน, รหัสวิชา, ชื่อวิชา, ชื่ออาจารย์, สถานะคำร้อง, ผลการประเมิน
- [ ] เพิ่มเมธอดใน `DashboardAnalyticsService`:
  - `getEvaluationExpiryAnalytics()`: ค้นหาคำร้องประเมินการสอนที่ได้ผลประเมิน (`carriesAPassedResult()`) คำนวณวันหมดอายุ และจัดกลุ่ม Active / Expiring Soon (<= 90 วัน) / Expired
  - `getYearlySubjectAnalytics(String academicYear)`: ดึงข้อมูลรายวิชาที่ยื่นประเมินจำแนกตามปีการศึกษา
  - `getAvailableAcademicYears()`: ดึงรายชื่อปีการศึกษาที่มีในระบบ (เช่น 2569, 2568, 2567) เพื่อสร้างตัวกรอง
  - `getPositionPipelineAnalytics()`: สรุปจำนวนคำร้องขอตำแหน่งแยกตามตำแหน่งเป้าหมาย (ผศ./รศ./ศ.) และสาขาวิชา
  - `getEvaluationQualityMetrics()`: สรุปอัตราผ่าน (%) และจำนวนจำแนกตามระดับผลประเมิน (ดีเด่น / ดีมาก / ดี)

### Phase 2: Controller Integration (`AcademicAdminController`)
- [ ] อัปเดต `@GetMapping("/dashboard")`:
  - รับ Request Parameter `@RequestParam(name = "year", required = false) String selectedYear`
  - ส่งข้อมูลชุดใหม่เข้าสู่ `Model`:
    - `expirySummary`: สรุปยอดคงเหลือ / ใกล้หมดอายุ / หมดอายุ
    - `expiryList`: รายการผลประเมินและวันหมดอายุ
    - `yearlySubjects`: รายการวิชาที่ยื่นในปีที่เลือก
    - `availableYears`: รายชื่อปีการศึกษาทั้งหมดสำหรับทำ Filter
    - `selectedYear`: ปีที่กำลังเลือกดูอยู่
    - `positionPipeline`: ข้อมูล Pipeline ผศ./รศ./ศ. และสาขา
    - `qualityMetrics`: อัตราผ่านและระดับผลประเมิน

### Phase 3: UI & Template Design (`dashboard.html` & CSS)
- [ ] **Expiry Alert & Watchlist Widget:**
  - สร้างแถบแจ้งเตือนเด่นชัด (Alert Banner / Mini Cards) แสดงจำนวนผลประเมินที่ใกล้หมดอายุใน 90 วัน
  - ตาราง Watchlist แสดงรายละเอียดชัดเจน พร้อม Badge สีสันแยกสถานะ (🟢 เขียว, 🟡 ส้มเตือน, 🔴 แดงหมดอายุ)
- [ ] **Yearly Subjects Section with Filter Tabs:**
  - Dropdown หรือ Button Pills เลือกปีการศึกษา (2569, 2568, ทั้งหมด)
  - ตารางแสดงรายวิชาที่ยื่นในแต่ละปี พร้อมรหัสวิชาและสถานะ
- [ ] **Pipeline & Quality Charts:**
  - เพิ่ม Chart แสดงสัดส่วนการขอตำแหน่ง (ผศ./รศ./ศ.) และระดับคุณภาพผลการประเมิน
- [ ] **Styling & Dark Theme:**
  - รองรับทั้ง Light และ Dark Theme ตามมาตรฐานของระบบ

### Phase 4: Testing & Verification
- [ ] เขียน/อัปเดต Unit Test สำหรับ `DashboardAnalyticsService`:
  - ทดสอบการคำนวณวันหมดอายุและการจัดกลุ่ม <= 90 วัน
  - ทดสอบการดึงรายวิชาจำแนกตามปีการศึกษา
- [ ] รัน `./mvnw test-compile` และ `./mvnw test` เพื่อตรวจสอบความถูกต้อง
- [ ] ตรวจสอบการแสดงผลในหน้าเว็บจริง
