# แผนงาน: ปรับปรุงข้อความสถานะบันทึกร่างอัตโนมัติให้กระชับและเข้าใจง่าย (Auto-Draft Wording Simplification)

> เอกสารแผนงานตามคำสั่ง `/plan` สำหรับการปรับข้อความสถานะใน `auto_draft.js` ให้สั้นลง ชัดเจน ตรงประเด็น และไม่สร้างความสับสนแก่ผู้ใช้

---

## 1. วัตถุประสงค์ (Objective)

1. **ลดความยาวของข้อความ (Conciseness):**
   - ข้อความเดิมค่อนข้างยาวและเป็นประโยคเชิงระบบ (System-centric) เช่น *"ระบบบันทึกร่างอัตโนมัติทำงานอยู่"* หรือ *"มีการแก้ไขที่ยังไม่บันทึก"* ทำให้ชิปสถานะมีขนาดกว้างเกินไปและดึงความสนใจจากเนื้อหาหลัก
2. **สร้างความมั่นใจและสื่อสารตรงไปตรงมา (User-centric):**
   - ปรับใช้คำสั้นๆ ที่ผู้ใช้คุ้นเคยตามมาตรฐานสากล (เช่น Google Docs, Microsoft 365, Notion) เช่น *"บันทึกแล้ว"*, *"กำลังบันทึก..."*, *"ยังไม่บันทึก"*
3. **รักษาความสอดคล้องทั้ง 2 ภาษา (TH & EN):**
   - คำภาษาไทยและภาษาอังกฤษจะต้องมีความหมายตรงกัน สั้นกระชับเท่าเทียมกันทั้งบนชิปสถานะ (`.adb`) และข้อความสรุปท้ายหน้า (`[data-autodraft-mirror]`)

---

## 2. ตารางเปรียบเทียบข้อความ (Comparison Table)

### 2.1 ข้อความบนชิปสถานะมุมลอย (`.adb`)

| สถานะ (State) | ไอคอน | ข้อความเดิม (ยาว) | ข้อความใหม่ที่เสนอ (สั้น กระชับ ชัดเจน) | ภาษาอังกฤษเดิม | ภาษาอังกฤษใหม่ |
|---|:---:|---|---|---|---|
| `idle` | `fa-cloud` | ระบบบันทึกร่างอัตโนมัติทำงานอยู่ | **บันทึกอัตโนมัติ** | Auto-save is active | **Auto-save on** |
| `dirty` | `fa-pen` | มีการแก้ไขที่ยังไม่บันทึก | **ยังไม่บันทึก** | Unsaved changes | **Unsaved** |
| `saving` | `fa-sync-alt` | กำลังบันทึกร่าง… | **กำลังบันทึก…** | Saving draft… | **Saving…** |
| `saved` | `fa-check-circle` | บันทึกร่างล่าสุด 14:30 น. | **บันทึกแล้ว 14:30 น.** | Draft saved 14:30 | **Saved 14:30** |
| `error` | `fa-exclamation-triangle` | บันทึกร่างไม่สำเร็จ — กรุณาลองใหม่ | **บันทึกไม่สำเร็จ** | Draft save failed — please retry | **Save failed** |
| `disabled` | `fa-pause-circle` | ปิดบันทึกร่างอัตโนมัติ | **ปิดบันทึกอัตโนมัติ** | Auto-save disabled | **Auto-save off** |

### 2.2 ข้อความสรุปข้างปุ่มส่งท้ายหน้า (`[data-autodraft-mirror]`)

> หมายเหตุ: บริเวณท้ายหน้ามีพื้นที่มากกว่า จึงให้ข้อมูลบริบทเพิ่มเติมได้เล็กน้อย แต่ตัดคำฟุ่มเฟือยออกเพื่อให้เข้าใจง่ายทันทีที่กวาดสายตามอง

| สถานะ (State) | ข้อความเดิม | ข้อความใหม่ที่เสนอ | ภาษาอังกฤษใหม่ |
|---|---|---|---|
| `idle` | ข้อมูลตรงกับที่บันทึกไว้ล่าสุด | **บันทึกข้อมูลล่าสุดเรียบร้อยแล้ว** | All changes saved |
| `dirty` | มีการแก้ไขที่ยังไม่บันทึก — ระบบจะบันทึกให้ก่อนส่ง | **มีข้อมูลยังไม่บันทึก (ระบบจะบันทึกให้อัตโนมัติ)** | Unsaved changes (will auto-save) |
| `saving` | กำลังบันทึกร่าง… | **กำลังบันทึกข้อมูล…** | Saving changes… |
| `saved` | บันทึกร่างล่าสุด 14:30 น. | **บันทึกข้อมูลแล้วเมื่อ 14:30 น.** | Saved at 14:30 |
| `error` | บันทึกร่างไม่สำเร็จ กรุณาลองใหม่ | **บันทึกไม่สำเร็จ กรุณาลองใหม่อีกครั้ง** | Save failed, please retry |
| `disabled` | ปิดบันทึกร่างอัตโนมัติ — ระบบจะบันทึกให้ตอนกดส่ง | **ปิดบันทึกอัตโนมัติ (จะบันทึกเมื่อกดส่ง)** | Auto-save off (saves on submit) |

## 4. แผนการทดสอบความถูกต้อง (Verification Plan)

1. **ตรวจสอบความกว้างของชิป (Visual & Layout Check):**
   - ชิปสถานะมีขนาดกะทัดรัดขึ้น ไม่กินพื้นที่จอ
   - เมื่อสถานะเปลี่ยนจาก `idle` -> `dirty` -> `saving` -> `saved` ชิปจะปรับขนาดอย่างนุ่มนวล ไม่กระตุก
2. **ตรวจสอบความเข้าใจของผู้ใช้ (Clarity):**
   - ผู้ใช้เห็น "บันทึกอัตโนมัติ" ทราบทันทีว่าระบบกำลังดูแลเรื่องการเซฟให้อยู่
   - เมื่อเริ่มพิมพ์ เห็น "ยังไม่บันทึก" ทราบว่ามีการเปลี่ยนแปลง
   - เมื่อระบบเซฟ เห็น "กำลังบันทึก..." แล้วเปลี่ยนเป็น "บันทึกแล้ว 14:30 น." ทราบทันทีว่าข้อมูลปลอดภัยแล้ว
3. **ตรวจสอบภาษาอังกฤษ (English Mode):**
   - สลับเป็น EN: แสดง "Auto-save on", "Unsaved", "Saving...", "Saved 14:30" ชัดเจนตามหลักสากล
