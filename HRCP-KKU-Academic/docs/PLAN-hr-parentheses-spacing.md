# PLAN-hr-parentheses-spacing.md - Fix Parentheses Spacing for HR Signer Name

## 1. Context & Root Cause Analysis

### ทำไมของนักทรัพยากรบุคคลถึงมีช่องว่างในวงเล็บ?
จากการตรวจสอบการทำงานของระบบสร้างและลงนามเอกสารดิจิทัลแบบ **Incremental PDF Signing (PAdES)** พบสาเหตุที่แท้จริงดังนี้:

1. **ความแตกต่างระหว่างช่องผู้ยื่นคำขอ vs ช่องนักทรัพยากรบุคคล:**
   - **ฝั่งผู้ยื่นคำขอ (ซ้าย):** ข้อมูลชื่อ (`title`, `applicant_name`) ถูกระบุและบันทึกไว้ตั้งแต่ผู้ยื่นส่งคำร้อง (`frozenJson`) ดังนั้นตอนสร้างเอกสารฉบับฐาน (Base PDF) ระบบแทนที่ข้อความลงใน Word template โดยตรงเป็น `(อาจารย์ผู้ยื่นคำขอ ทดสอบ)` แล้วแปลงเป็น PDF วงเล็บจึงแนบชิดกับชื่อพอดี
   - **ฝั่งนักทรัพยากรบุคคล (ขวา):** ในเอกสารที่ 2 (แบบตรวจสอบเบื้องต้นฯ) มีสถานะเป็น `REVIEWER_SIGNED` และอยู่ใน `ADMIN_FIELDS` / `lateFields` ของ `DocumentFieldOwnership` เพราะขณะที่ผู้ยื่นสร้างเอกสาร ยังไม่มีใครทราบว่าเจ้าหน้าที่ HR คนใดจะเป็นผู้ตรวจและลงนาม
   
2. **กลไกการจองพื้นที่ของ `BasePdfBuilder`:**
   - สำหรับ late field ที่เป็นชื่อบุคคล (`field.contains("name")`) ระบบจะจองพื้นที่ล่วงหน้าด้วย Non-breaking space (`NBSP`) จำนวน **45 ตัวอักษร** (`reserveFor("hr_staff_name") = 45`)
   - ในเทมเพลต Word (`doc_2.docx`) มีข้อความเดิมคือ `<w:t>({{hr_staff_name}})</w:t>`
   - เมื่อ `BasePdfBuilder.reserve` ทำการแทนที่ `@@OVL_hr_staff_name@@` ด้วย NBSP 45 ตัว เนื้อหาใน Word จึงกลายเป็น `(` + **45 NBSP** + `)`
   - LibreOffice ทำการแปลงเอกสารนี้เป็น Base PDF (Revision 0) ส่งผลให้วงเล็บเปิด `(` และวงเล็บปิด `)` ถูกพิมพ์เป็น **ตัวอักษรตายตัวบนพื้นหลังของหน้า PDF (Static Background Text)** ห่างกันตามความกว้างของช่องว่าง 45 ตัวอักษร (กว้างประมาณ 155pt)
   - จากนั้น `BasePdfBuilder` สร้าง AcroForm Text Widget ชื่อ `hr_staff_name` วางทับอยู่ระหว่างวงเล็บคู่นั้น

3. **จังหวะที่ HR ลงนามจริง (Incremental Signing):**
   - เมื่อเจ้าหน้าที่ HR ทำการตรวจและกดลงนาม (Revision 1): `IncrementalSigningService` จะดึงชื่อของเจ้าหน้าที่ (`นางสาวเจ้าหน้าที่HR ทดสอบ`) ส่งให้ `PdfIncrementService.fillField` โดยระบุ `centred = true`
   - `PdfIncrementService` คำนวณความกว้างของชื่อ (ยาวประมาณ 24 ตัวอักษร ≈ 85pt) แล้วนำไปวาด **กึ่งกลาง (Center)** ภายในกรอบ Widget ที่กว้าง 155pt
   - **ผลลัพธ์ที่ปรากฏ:** ตัวหนังสือชื่อเจ้าหน้าที่อยู่ตรงกลาง ส่วนวงเล็บ `(` และ `)` เป็นของพื้นหลัง PDF ที่ห่างออกไปที่ขอบซ้ายและขอบขวา จึงเห็นเป็นช่องว่างขนาดใหญ่:
     ```
     (          นางสาวเจ้าหน้าที่HR ทดสอบ          )
     ```

## 2. Solution Strategy

เพื่อแก้ปัญหานี้ให้สมบูรณ์ โดยไม่กระทบความถูกต้องของลายมือชื่อดิจิทัลและไฟล์ Word DOCX:

### แนวทางแก้ไข: ย้ายวงเล็บให้มาวาดพร้อมตัวข้อความแทนการพิมพ์ตายตัวในพื้นหลัง PDF
1. **ใน `BasePdfBuilder.reserve(...)`:**
   - เมื่อทำการ reserve ฟิลด์ข้อความ หากตรวจพบว่า placeholder token ถูกครอบด้วยวงเล็บเปิด-ปิดใน text run เช่น `(@@OVL_<field>@@)` หรือ `( @@OVL_<field>@@ )` ให้ทำการตัดวงเล็บ `(` ด้านหน้า และ `)` ด้านหลัง ออกจากไฟล์ Word ฉบับฐาน
   - ส่งผลให้ Base PDF ที่ LibreOffice เรนเดอร์ออกมา จะมีเฉพาะช่องว่างสำหรับวาง Widget โดย**ไม่มีวงเล็บตายตัว**ค้างอยู่บนพื้นหลัง PDF
2. **ใน `PdfIncrementService.fillField(...)`:**
   - เมื่อทำการวาดข้อความสำหรับฟิลด์ที่เป็น `centred = true` (ซึ่งใช้กับช่องชื่อผู้ลงนาม `nameField`)
   - หากข้อความที่ได้รับยังไม่ได้ครอบด้วยวงเล็บ (`!text.startsWith("(") || !text.endsWith(")")`) ให้ทำการครอบวงเล็บเข้ากับข้อความก่อน:
     `textToDraw = "(" + text + ")";`
   - เมื่อวาดข้อความพร้อมวงเล็บเป็นเนื้อเดียวกัน ฟอนต์จะวาง `(` ชิดหน้าชื่อ และ `)` ชิดท้ายชื่อพอดี แล้วจัดกึ่งกลางทั้งก้อนใต้เส้นลงนาม
3. **ความเข้ากันได้กับไฟล์ Word DOCX:**
   - ใน `doc_2.docx` ยังคงมี `({{hr_staff_name}})` ตามเดิม ทำให้การดาวน์โหลดหรือพรีวิวเป็น Word DOCX จะยังคงได้รูปแบบ `(ชื่อ-สกุล)` ถูกต้องตามมาตรฐานหนังสือราชการ และเทสต์เดิม (`SignerNameOnDocumentTest`) จะยังคงผ่าน 100%

## 3. Task Breakdown

### Task 1: ปรับปรุง `BasePdfBuilder.java` (Docx Reserve Logic)
- ในเมธอด `reserve(...)`:
  - ตรวจสอบ `xml.substring(tEnd + 1, at)` และ `xml.substring(at + token.length())`
  - หากพบรูปแบบครอบวงเล็บ `(...)` รอบ token ให้ตัด `(` และ `)` ออกจาก text run ของฉบับฐาน

### Task 2: ปรับปรุง `PdfIncrementService.java` (PDF Field Stamping Logic)
- ในเมธอด `fillField(...)`:
  - ตรวจสอบกรณี `centred == true` และข้อความไม่ว่าง:
  - หากยังไม่มีวงเล็บครอบ ให้เติม `(` และ `)` เข้ากับสตริงข้อความก่อนคำนวณ `thai.width(...)` และเรียก `thai.operators(...)`

### Task 3: Unit Tests & Verification
- อัปเดตและเพิ่ม Test Case ใน `SignerNamePrintingTest.java` หรือสร้าง Test ใหม่เพื่อยืนยันว่า:
  1. Base PDF ที่ได้จาก `BasePdfBuilder` ไม่มีวงเล็บตายตัวห้อยค้าง
  2. เมื่อเติมชื่อลงในช่อง `hr_staff_name` แล้ว ข้อความที่เรนเดอร์มีวงเล็บแนบชิดชื่อ เช่น `(นางสาวเจ้าหน้าที่HR ทดสอบ)`
  3. รัน `./HRCP-KKU-Academic/mvnw test` ทุกเทสต์ที่เกี่ยวข้องกับ PDF และ Signer ให้ผ่านสมบูรณ์ 100%
