# ข้อเสนอ: ผู้ลงนามจากนอกวิทยาลัย (External Signer)

**รหัสเอกสาร:** `docs/PLAN-external-signer.md`
**สถานะ:** ข้อเสนอ — รอเลือกแนวทาง
**ที่มา:** `PLAN-signer-picker.md` ข้อ 6 คำถามที่ 4

---

## 1. โจทย์

ผู้ประพันธ์อันดับแรก / ผู้ประพันธ์บรรณกิจ (เฟส 2 ฉบับ 9) อาจอยู่นอก มข. จึงไม่มีบัญชีในระบบ
แต่ต้องลงนามรับรองการมีส่วนร่วมในผลงาน — ผู้ใช้เสนอ: *"ใส่อีเมลเพื่อให้เขากดมาเซ็นได้ (รองรับแบบไม่มีบัญชีในระบบ)"*

ข้อจำกัดที่ต้องคิดคู่กัน:
1. **ยืนยันตัวตน** — ลิงก์ในอีเมลอย่างเดียว ใครได้อีเมลต่อก็เซ็นแทนได้
2. **ใบรับรองในไฟล์** — ทุกคนที่ลงนามต้องขึ้นใบรับรองใน Foxit/Adobe (ข้อกำหนดเดิม) แต่คนนอก มข. ไม่มี Digital ID ของ มข.
3. **ไม่เห็นข้อมูลเกินจำเป็น** — คนนอกต้องเห็นเฉพาะเอกสารที่ตัวเองต้องลงนาม (PDPA)

## 2. แนวทางที่เสนอ: เชิญเป็นบัญชีภายนอกทางอีเมล

แทนที่จะสร้างทางลงนามคู่ขนานแบบไม่มีบัญชี ให้ระบบ **สร้างบัญชีภายนอกให้อัตโนมัติจากอีเมล** แล้วใช้ทางลงนามเดิมทั้งหมด

| ขั้น | เกิดอะไรขึ้น |
|---|---|
| 1. ระบุผู้ลงนาม | ในตัวค้นหาชื่อ ถ้าไม่พบ → "เพิ่มผู้ลงนามนอก มข." กรอก ชื่อ-สกุล + คำนำหน้า, อีเมล, หน่วยงาน |
| 2. สร้างบัญชี | บทบาทใหม่ `ROLE_EXTERNAL` — ไม่มีรหัสผ่าน เข้าได้เฉพาะ "งานลงนามของฉัน" และหน้าลงนามของตัวเอง |
| 3. เชิญทางอีเมล | ลิงก์ใช้ครั้งเดียว หมดอายุใน 7 วัน (ใช้กลไก reset token ที่มีอยู่) → ตั้งรหัสผ่าน + ยืนยัน OTP ทางอีเมล (มีอยู่แล้ว) |
| 4. ลงนาม | หน้าลงนามเดิม: ลายเซ็น + Digital ID (.p12) ของเขาเอง + PIN — ใบรับรองขึ้นในไฟล์เหมือนทุกคน |
| 5. หลังลงนาม | บัญชียังอยู่ (ประวัติ/หลักฐาน) — ถ้าต้องลงนามอีกครั้งในอนาคต ใช้บัญชีเดิม |

**ทำไมดีกว่าลิงก์ไม่มีบัญชี:** กล่องงาน, การแจ้งเตือน, ประวัติการลงนาม, การตรวจสอบหลักฐาน, การยกเลิก/ขยายเวลา ใช้ของเดิมได้ทั้งหมด
ไม่มีทางลงนามที่สองให้ดูแลและตรวจความปลอดภัยแยก และผู้ลงนามคนนอกได้หลักฐานระดับเดียวกับคนใน

## 3. เรื่องที่ต้องเลือก: คนนอกที่ไม่มี Digital ID

Digital ID (.p12) ของ มข. ออกให้เฉพาะบุคลากร มข. คนนอกบางคนมีของหน่วยงานตัวเอง บางคนไม่มี

| ทางเลือก | ใบรับรองในไฟล์ | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A. บังคับ .p12 ของหน่วยงานตัวเอง** | ของผู้ลงนามเอง | เข้มเท่าคนใน | คนที่ไม่มีลงนามไม่ได้เลย คำร้องติด |
| **B. ไม่มี .p12 → ระบบประทับรับรองแทน** (เสนอ) | ของระบบ (ใบรับรองของหน่วยงาน/ระบบ HRD) พร้อมเหตุผล "ลงนามโดย <ชื่อ> ยืนยันตัวตนทางอีเมล <อีเมล> เมื่อ <เวลา>" | ทุกคนลงนามได้ ไฟล์ยังขึ้นใบรับรองครบทุกขั้น | ต้องมีใบรับรองของหน่วยงานสำหรับระบบ 1 ใบ และน้ำหนักทางหลักฐานต่ำกว่าแบบ A |
| C. ไม่มี .p12 → ลงนามแบบไม่มีใบรับรอง | ไม่มี | ทำง่ายสุด | ขัดข้อกำหนด "ทุกคนต้องขึ้นใบรับรอง" |

**เสนอ:** รองรับ A เป็นหลัก (มี .p12 → ใช้ของตัวเอง) และ B เป็นทางสำรองสำหรับคนที่ไม่มี
— B ต้องการ **ใบรับรองของหน่วยงาน (.p12) สำหรับระบบ** หนึ่งใบ ซึ่งต้องขอจากผู้ดูแล Digital ID ของ มข.

## 4. ขอบเขตงาน (ประมาณ)

1. บทบาท `ROLE_EXTERNAL` + สิทธิ์ (Spring Security): เข้าได้เฉพาะ `/esign/inbox`, `/esign/sign/**` ของขั้นตัวเอง, หน้าโปรไฟล์/ลายเซ็น/Digital ID ของตัวเอง
2. ตัวค้นหาชื่อ: ปุ่ม "เพิ่มผู้ลงนามนอก มข." + ฟอร์มชื่อ/อีเมล/หน่วยงาน (กันอีเมลซ้ำกับบัญชีที่มีอยู่)
3. อีเมลเชิญ + ลิงก์ตั้งรหัสผ่านใช้ครั้งเดียว + OTP
4. (ถ้าเลือก B) ใบรับรองระบบ + ขั้นยืนยันตัวตนทางอีเมลก่อนลงนาม + ประทับรับรองในนามระบบ
5. เทส: สิทธิ์ของบัญชีภายนอก (เข้าเอกสารอื่นไม่ได้), เชิญ → ตั้งรหัส → ลงนาม, ลิงก์หมดอายุ/ใช้ซ้ำไม่ได้
