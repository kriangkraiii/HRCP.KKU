# Plan: Formal & Cohesive Academic Dashboard Redesign (ปรับปรุงแดชบอร์ดทางการและเชื่อมโยงข้อมูล)

## 📌 Context & Problem
ผู้ใช้งานส่งภาพหน้าจอ 2 ส่วนที่ต้องการนำออกและแจ้งข้อปรับปรุงชัดเจน:
1. **เอาออก (Remove Noisy / Irrelevant Widgets):**
   - **กราฟ "ผู้ใช้ใหม่รายเดือน" (Monthly New Users):** ข้อมูลไม่เกี่ยวข้องกับงานบุคคลวิชาการและการประเมินผลการสอน
   - **ตาราง "กิจกรรมล่าสุด" (Recent Admin Activity):** ปัจจุบันบันทึก Web Traffic ทั่วไป (เช่น `GET /vendor/fonts/...`, `PAGE_VIEW`) ซึ่งเป็น log ขยะทางเทคนิค ไม่ใช่การกระทำเชิงวิชาการ
   - **การ์ด KPI "ผู้ใช้ในระบบ":** ควรเปลี่ยนเป็นตัวชี้วัดสำคัญของกระบวนการวิชาการแทน (เช่น คำร้องที่ส่งเรื่อง กอง ทบ. มข. แล้ว หรือคำร้องที่ผ่านการรับรอง)
2. **ลบอิโมจิออกทั้งหมด (Remove All Emojis for Formal University Academic Tone):**
   - ลบอิโมจิ เช่น ⚡, ⚠️, ⏳, ❌, 📋, 🔥, 🟢, 🟡, 🔴 ออกทั้งหมด
   - ปรับใช้ไอคอนทางการของ FontAwesome (เช่น `fa-clock`, `fa-circle-exclamation`, `fa-circle-check`, `fa-graduation-cap`) ร่วมกับป้ายกำกับข้อความภาษาทางการ (Official Academic Thai)
3. **ปรับปรุงความเชื่อมโยงของทั้งหน้า (Unified & Cohesive Dashboard Architecture):**
   - เดิมหน้าแดชบอร์ดถูกเพิ่มเนื้อหาทีละส่วนจนกลายเป็น 6 แถวยาวที่ไม่เชื่อมโยงกัน (Disjointed)
   - ปรับโครงสร้างหน้าใหม่ให้เป็น **3 ระดับลำดับชั้น (3-Tier Hierarchical Dashboard)** ที่ร้อยเรียงกระบวนการวิชาการตั้งแต่ต้นน้ำถึงปลายน้ำอย่างกลมกลืน

---

## 🎯 Proposed Architecture: 3-Tier Cohesive Layout

### Tier 1: Executive KPI Banner (ภาพรวมตัวชี้วัดหลักของผู้บริหาร - 5 การ์ดทางการ)
ปรับแถบ KPI ด้านบนให้สะท้อนวงจรคำร้องวิชาการทั้งหมด (ตัด "ผู้ใช้ในระบบ" ออก):
1. **คำร้องทั้งหมด (Total Requests):** รวมทั้งประเมินการสอนและขอกำหนดตำแหน่ง
2. **กำลังดำเนินการ (Active / In-Flight):** คำร้องที่อยู่ระหว่างขั้นตอนตรวจสอบ / กรรมการ / นัดประชุม
3. **ผ่านการประเมินการสอน (Passed Evaluations):** จำนวนคำร้องที่ผ่านการรับรอง (พร้อมอัตราผ่าน Pass Rate %)
4. **ส่งเรื่อง มข. สำเร็จ (Sent to KKU HR):** คำร้องขอกำหนดตำแหน่งที่วิทยาลัยฯ ส่งเรื่องไปยังมหาวิทยาลัยแล้ว (ขั้นตอนปลายทางสำเร็จ)
5. **เฝ้าระวังวันหมดอายุ (Expiry Watch):** ผลประเมินที่ต้องติดตาม (ใกล้หมดอายุใน 90 วัน)

---

### Tier 2: Strategic Insights & Pipeline (กราฟวิเคราะห์เชิงกลยุทธ์ - 2 คอลัมน์สมดุล)
จัดวางกราฟให้เชื่อมโยงกัน ไม่กระจัดกระจาย:
- **ฝั่งซ้าย (60% — คำร้องและแนวโน้ม):**
  - กราฟแท่งแนวโน้มคำร้องรายเดือน (ย้อนหลัง 12 เดือน) แยกตาม "ประเมินผลการสอน" vs "ขอกำหนดตำแหน่ง"
  - มีสวิตช์ย่อยดูสัดส่วนสถานะคำร้อง (Status Breakdown)
- **ฝั่งขวา (40% — ตำแหน่งทางวิชาการและสาขาวิชา):**
  - กราฟสัดส่วนตำแหน่งเป้าหมาย (ผศ. / รศ. / ศ.)
  - กราฟแท่งจำแนกตามสาขาวิชาหลัก (วิทยาการคอมพิวเตอร์, เทคโนโลยีสารสนเทศ ฯลฯ)
  - สรุประดับคุณภาพผลการประเมิน (ดีเด่น / ดีมาก / ดี)

---

### Tier 3: Operational Lifecycle Hub (ศูนย์ข้อมูลการดำเนินงานแบบแท็บเดียวเชื่อมโยง)
รวมตารางที่เคยแยกกัน ให้เชื่อมต่อกันด้วย **แท็บนำทางระดับทางการ (Executive Tabs)**:
- **แท็บ 1: เฝ้าระวังวันหมดอายุผลประเมินการสอน (Evaluation Expiry & Position Tracking):**
  - แถบสรุป 4 กล่องสถานะ (ไม่มีอิโมจิ):
    - ผลประเมินมีผลสมบูรณ์ (>90 วัน)
    - ใกล้หมดอายุภายใน 90 วัน
    - สิ้นผลการประเมิน (หมดอายุ)
    - ยังไม่ยื่นขอกำหนดตำแหน่ง
  - ตัวกรองสถานะแบบปุ่มข้อความสุภาพ (เช่น [ทั้งหมด], [เร่งด่วน 30 วัน], [ใกล้หมดอายุ 90 วัน], [หมดอายุแล้ว], [ยังไม่ยื่นตำแหน่ง])
  - ตารางติดตามผลประเมิน: รหัสคำร้อง, อาจารย์ผู้ยื่น, รายวิชา, วันที่ผ่าน, วันที่หมดอายุ, จำนวนวันคงเหลือ, สถานะการนำไปยื่นตำแหน่ง
- **แท็บ 2: สถิติรายวิชาที่ยื่นประเมินจำแนกตามปีการศึกษา (Course Submissions by Academic Year):**
  - ตัวกรองเลือกปีการศึกษา: [ทั้งหมด], [ปีการศึกษา 2569], [ปีการศึกษา 2568]...
  - แถบสรุปรายวิชาที่มีการยื่นประเมินสูงสุด (Top Evaluated Courses)
  - ตารางรายวิชาที่ยื่น: รหัสคำร้อง, ปีการศึกษา/ภาค, รหัสวิชา, ชื่อวิชา, ผู้ยื่น, สถานะ, ระดับผลประเมิน

## ❓ Socratic Gate & Clarification for User
1. **การ์ด KPI ช่องที่ 3 และ 4:**
   - จากเดิมที่เป็น "ผู้ใช้ในระบบ" ทางเราเสนอเปลี่ยนเป็น **"ส่งเรื่อง มข. แล้ว (Completed/Sent to HR)"** และเพิ่มการ์ด **"เฝ้าระวังหมดอายุ (Expiring Soon)"** เพื่อให้เป็นตัวชี้วัดงานวิชาการ 100% ท่านเห็นชอบหรือไม่?
2. **การรวมตารางด้วยระบบแท็บ (Tab Navigation):**
   - การรวม "ตารางเฝ้าระวังวันหมดอายุ" และ "ตารางสถิติรายวิชาตามปีการศึกษา" เข้าเป็นแท็บในกล่องเดียวกัน จะช่วยให้หน้าเว็บกระชับขึ้น ไม่ต้องเลื่อนยาว และสลับดูข้อมูลได้รวดเร็ว ท่านเห็นชอบหรือไม่?
