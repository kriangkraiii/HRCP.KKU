# แผนงาน: บังคับแนบเอกสารประเมินการสอน และส่งหนังสือเชิญถึงกรรมการทางอีเมล

**รหัสเอกสาร:** `docs/PLAN-required-attachment-committee-email.md`
**สถานะ:** ดำเนินการแล้ว (Implemented & Tested)

---

## 1. ความต้องการ

> ตอนนี้การยื่นขอประเมินการสอนไม่บังคับแนบเอกสาร เปลี่ยนเป็นบังคับ เพราะในเอกสารที่ 5 ต้องแนบเอกสารของผู้ยื่นไปให้กรรมการทั้งสามคน
> ให้ส่งเอกสารของผู้ยื่นไปกับอีเมล กรรมการดูผ่านอีเมลที่ส่งไป

ข้อตกลงกับผู้ใช้:

| ประเด็น | ข้อสรุป |
|---|---|
| ส่งไฟล์ของผู้ยื่นอย่างไร | ไม่แนบไฟล์ของผู้ยื่นในอีเมล (รวมได้ถึง 75 MB เกินที่ SMTP รับ) — อีเมลมีปุ่มพากรรมการมาเปิดดูไฟล์ในระบบ |
| ลิงก์ (URL) นับเป็นเอกสารแนบไหม | นับ |
| ส่งเมื่อไร | อัตโนมัติทันทีที่เอกสารที่ 5 ลงนามครบ |
| คำร้องเก่าที่ไม่มีไฟล์แนบ | ยังส่งหนังสือเชิญได้ หน้าแอดมินเตือนว่าไม่มีเอกสารของผู้ยื่น |

## 2. ฝั่งผู้ยื่น — บังคับแนบเอกสาร

| จุด | การเปลี่ยนแปลง |
|---|---|
| `document_2_form.html` | ป้าย "บังคับ" แทน "ไม่บังคับ"; JS ไม่ให้บันทึก/ส่งลงนามจนกว่าจะมีไฟล์หรือลิงก์อย่างน้อย 1 รายการ |
| `AcademicApplicantController.submitDocument2` | `action=submit` ที่ไม่มีไฟล์แนบ → ไม่บันทึก เด้งกลับ `?error=no_attachments` (บันทึกร่างยังทำได้) |
| `AcademicApplicantController.submitRequest` | ตรวจซ้ำตอนยื่นคำร้อง — กันเอกสารที่ 2 ที่บันทึกก่อนมีกติกานี้ หรือไฟล์ถูกลบหลังบันทึก |
| `AcademicApplicantController.newRequest` | เอกสารที่ 2 นับว่า "ครบ" เมื่อมีไฟล์แนบด้วย |

## 3. ฝั่งกรรมการ — อีเมลหนังสือเชิญ

```
ซองเอกสารที่ 5 ลงนามครบ
  └─ SignedDocumentStatusAdvancer.advanceFor
       └─ CommitteeDocumentMailer.sendWhenSigned (@Async)
            ├─ ผูกชื่อในหนังสือ (committee_name_1..3) กับบัญชี — ผ่าน NamedAccountResolver
            │    ใช้รหัสบัญชีจากเอกสารที่ 3/4 เมื่อชื่อยังตรงกับคำสั่งแต่งตั้ง
            ├─ สร้างไฟล์หนังสือครั้งเดียวแล้วตัดเป็น 3 ฉบับ (PDF; แปลงไม่ได้ส่ง DOCX)
            ├─ อีเมลแยกท่านละฉบับ: แนบหนังสือของท่าน + รายชื่อไฟล์ + ลิงก์ที่ผู้ยื่นแนบ + ปุ่มเปิดดูไฟล์
            ├─ แจ้งเตือนในระบบถึงกรรมการ (ลิงก์ไปหน้าเดียวกัน)
            └─ บันทึกประวัติเอกสาร (COMMITTEE_EMAILED)
```

- **ส่งทั้งหมดหรือไม่ส่งเลย:** ถ้าผูกบัญชีกรรมการท่านใดไม่ได้ หรือสร้างหนังสือไม่ได้ จะไม่ส่งถึงใคร และแจ้งแอดมินพร้อมเหตุผล
- **ส่งซ้ำ:** ปุ่ม "ส่งอีกครั้ง" ใต้หนังสือฉบับที่ 1–3 ในหน้ารายละเอียดคำร้อง (`POST /admin/academic/request/{id}/document/5/email-committee`)

### หน้าเปิดดูเอกสารของผู้ยื่น

`GET /esign/committee/academic/{requestId}` และ `.../attachment/{attachmentId}` ใน `SigningController`

- เปิดได้เฉพาะกรรมการสามท่านตามคำสั่งแต่งตั้งในเอกสารที่ 4 (`AcademicRequestService.isAppointedCommitteeMember`) และแอดมิน/เจ้าหน้าที่
- คนอื่น (รวมถึงผู้ยื่นเอง) ได้ "ไม่พบ" ไม่บอกว่าคำร้องมีอยู่
- อยู่ใต้ `/esign/**` เพื่อให้ทั้ง ROLE_USER และผู้ใช้ภายนอก (ROLE_EXTERNAL) เข้าได้
- ไฟล์ DOCX แปลงเป็น PDF ให้อ่านในเบราว์เซอร์ ใช้โค้ดเดียวกับไฟล์แนบในหน้าลงนาม

### ข้อจำกัดที่ทราบ

หลังเข้าสู่ระบบ ระบบพาไปหน้าแรกของบทบาท ไม่ใช่ลิงก์ที่กดมา (พฤติกรรมเดิมของการเข้าสู่ระบบทุกทาง)
กรรมการที่ยังไม่ได้เข้าระบบจึงต้องกดปุ่มในอีเมลอีกครั้ง หรือกดจากกระดิ่งแจ้งเตือน

## 4. การทดสอบ

- `RequiredAttachmentNoticeTest` — ป้ายบังคับ, บันทึกโดยไม่มีไฟล์ถูกปฏิเสธ, ลิงก์นับเป็นไฟล์แนบ, บันทึกร่างได้, ยื่นคำร้องโดยไม่มีไฟล์ถูกปฏิเสธ
- `CommitteeInvitationEmailTest` — ลงนามครบแล้วกรรมการแต่ละท่านได้อีเมลพร้อมหนังสือฉบับของตัวเอง, คำร้องที่ไม่มีไฟล์ยังส่งได้, ผูกบัญชีไม่ได้ไม่ส่งถึงใคร, สิทธิ์เปิดหน้าเอกสาร
