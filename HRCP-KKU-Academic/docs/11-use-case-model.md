# แบบจำลองยูสเคส (Use Case Model)

ระบบเอกสารและการติดตามผลการยื่นขอกำหนดตำแหน่งทางวิชาการ
วิทยาลัยการคอมพิวเตอร์ มหาวิทยาลัยขอนแก่น

---

## 1. ผู้กระทำ (Actors)

### 1.1 Primary Actors (ผู้ใช้งานระบบ)

| รหัส | ผู้กระทำ | คำอธิบาย | ที่มาของบทบาทในระบบ |
|------|---------|----------|---------------------|
| A-01 | ผู้ใช้ทั่วไป (Guest) | ผู้ที่ยังไม่ผ่านการยืนยันตัวตน เข้าถึงได้เฉพาะหน้าเข้าสู่ระบบ การกู้คืนรหัสผ่าน และการตรวจสอบความถูกต้องของลายเซ็น | — |
| A-02 | ผู้ยื่นคำร้อง (Applicant) | บุคลากรสายวิชาการที่ยื่นขอประเมินผลการสอนหรือขอกำหนดตำแหน่งทางวิชาการ | ช่องลงนาม `applicant` |
| A-03 | ผู้ประพันธ์ร่วม (Co-author) | ผู้ประพันธ์อันดับแรกและผู้ประพันธ์บรรณกิจของผลงานทางวิชาการ ที่ต้องลงนามรับรองการมีส่วนร่วมในผลงาน | ช่องลงนาม `first_author`, `corresponding_author` |
| A-04 | หัวหน้าสาขาวิชา (Department Head) | ผู้บังคับบัญชาชั้นต้นของผู้ยื่นคำร้อง ลงนามรับรองในลำดับแรกของสายบังคับบัญชา | ช่องลงนาม `head` (staffRole = HEAD) |
| A-05 | รองคณบดี (Associate Dean) | ลงนามกลั่นกรองเอกสารก่อนเสนอคณบดี | ช่องลงนาม `associate_dean` (staffRole = DEAN) |
| A-06 | คณบดี (Dean) | ผู้ลงนามอนุมัติในลำดับสูงสุดของวิทยาลัย และลงนามในหนังสือนำส่งไปยังมหาวิทยาลัย | ช่องลงนาม `dean` (staffRole = DEAN) |
| A-07 | เจ้าหน้าที่บุคคล (HR Officer) | นักทรัพยากรบุคคลและเจ้าหน้าที่บริหารงาน ผู้ตรวจสอบความถูกต้องครบถ้วนของเอกสารและลงนามรับรอง | ช่องลงนาม `hr` (staffRole = HR) |
| A-08 | ประธานคณะกรรมการประเมิน (Committee Chair) | ประธานคณะกรรมการประเมินผลการสอนหรือประธานคณะอนุกรรมการ ผู้ลงนามรับรองผลการประเมิน | ช่องลงนาม `committee_chair` (staffRole = COMMITTEE) |
| A-09 | ผู้ทรงคุณวุฒิภายนอก (External Reader) | ผู้ทรงคุณวุฒิจากสถาบันภายนอกที่ได้รับแต่งตั้งให้ประเมินผลงานทางวิชาการ | ทะเบียนคณะกรรมการ ประเภท EXTERNAL_READER |
| A-10 | ผู้ดูแลระบบ (Admin) | เจ้าหน้าที่ผู้ดูแลคำร้อง ผู้ใช้ ไฟล์ การตั้งค่าระบบ และการเชื่อมโยงข้อมูลภายนอก — สืบทอดจาก A-02 | ROLE_ADMIN |

**หมายเหตุเรื่องการสืบทอด:** ผู้กระทำ A-02 ถึง A-10 ทุกตัวสืบทอดยูสเคสของ A-01 (ผู้ใช้ทั่วไป) เนื่องจากทุกคนต้องเข้าสู่ระบบผ่านช่องทางเดียวกัน เพื่อไม่ให้แผนภาพซับซ้อนเกินความจำเป็น ความสัมพันธ์นี้จึงระบุไว้เป็นหมายเหตุกำกับในแผนภาพระดับบริบทแทนการวาดเส้นสืบทอดของผู้กระทำทุกตัว ยกเว้นความสัมพันธ์ระหว่างผู้ดูแลระบบกับผู้ยื่นคำร้องที่แสดงเป็นเส้นสืบทอดตามปกติ

**ผู้กระทำที่มีอำนาจลงนาม:** A-02 ถึง A-09 คือกลุ่มผู้กระทำที่สามารถลงนามในเอกสารได้ เอกสารแต่ละประเภทกำหนดว่าต้องมีผู้ลงนามตำแหน่งใดบ้างและลงนามตามลำดับใด ในเอกสารฉบับนี้จะอ้างถึงกลุ่มนี้ด้วยข้อความ "ผู้มีอำนาจลงนาม (A-02 ถึง A-09)"

### 1.3 ความสัมพันธ์ระหว่างผู้กระทำกับสิทธิ์การใช้งานในระบบ

ผู้กระทำในแบบจำลองนี้เป็น **บทบาทเชิงหน้าที่ (functional role)** ตามหลักการของ UML ซึ่งหมายถึงบทบาทที่ผู้ใช้สวมขณะมีปฏิสัมพันธ์กับระบบ มิใช่สิทธิ์ทางเทคนิคที่จัดเก็บในฐานข้อมูล ระบบกำหนดสิทธิ์ทางเทคนิคไว้เพียงสองระดับ คือ ROLE_USER และ ROLE_ADMIN ซึ่งใช้ควบคุมการเข้าถึงหน้าจอบริหารระบบเท่านั้น

ส่วนบทบาทของผู้ลงนามกำหนดเป็นรายเอกสารผ่านผังลำดับผู้ลงนาม (`SignatureAnchorRegistry` และ `DocumentWorkflowConfig`) ซึ่งระบุว่าเอกสารแต่ละประเภทมีช่องลงนามตำแหน่งใดบ้าง ลำดับที่เท่าใด และจับคู่กับบุคลากรผู้ใดในทะเบียน ส่วนกรรมการและผู้ทรงคุณวุฒิกำหนดผ่านทะเบียนคณะกรรมการ (`AcademicCommitteeMember`)

| ผู้กระทำ | สิทธิ์ทางเทคนิค | กลไกกำหนดบทบาท |
|---------|----------------|------------------|
| A-02 ผู้ยื่นคำร้อง | ROLE_USER | เป็นเจ้าของคำร้องนั้น |
| A-03 ผู้ประพันธ์ร่วม | ROLE_USER | ระบุชื่อไว้ในเอกสารรับรองการมีส่วนร่วมในผลงาน |
| A-04 หัวหน้าสาขาวิชา | ROLE_USER | ทะเบียนบุคลากร staffRole = HEAD |
| A-05 รองคณบดี | ROLE_USER | ทะเบียนบุคลากร staffRole = DEAN |
| A-06 คณบดี | ROLE_USER | ทะเบียนบุคลากร staffRole = DEAN |
| A-07 เจ้าหน้าที่บุคคล | ROLE_USER | ทะเบียนบุคลากร staffRole = HR |
| A-08 ประธานคณะกรรมการประเมิน | ROLE_USER | ทะเบียนบุคลากร staffRole = COMMITTEE |
| A-09 ผู้ทรงคุณวุฒิภายนอก | ROLE_USER | ทะเบียนคณะกรรมการ ประเภท EXTERNAL_READER ซึ่งได้รับสิทธิ์เข้าใช้ระบบผ่าน SSO เป็นกรณีพิเศษ |
| A-10 ผู้ดูแลระบบ | ROLE_ADMIN | กำหนดโดยผู้ดูแลระบบเดิม |

> **ข้อสังเกตสำคัญ:** สิทธิ์ทางเทคนิคกับอำนาจลงนามไม่มีความสัมพันธ์กัน ผู้ลงนามทุกตำแหน่งตั้งแต่หัวหน้าสาขาวิชาจนถึงคณบดีมีสิทธิ์ทางเทคนิคเพียง ROLE_USER เท่านั้น ขณะที่ผู้ดูแลระบบซึ่งมีสิทธิ์ ROLE_ADMIN เป็นเจ้าหน้าที่ธุรการที่ไม่มีอำนาจลงนามในเอกสารเชิงบริหาร ด้วยเหตุนี้ระบบจึงออกแบบให้ส่วนการลงนาม (`/esign`) อยู่นอกเส้นทางที่ควบคุมด้วยสิทธิ์ทางเทคนิค เพื่อให้ผู้ใช้ทุกระดับที่ได้รับมอบหมายสามารถลงนามได้
>
> การแยกผู้กระทำตามตำแหน่งจริงเช่นนี้ยังสะท้อนความจริงว่าผู้ใช้คนเดียวกันสวมได้หลายบทบาทตามบริบทของงาน เช่น คณบดีเป็นทั้งผู้ยื่นคำร้องของตนเอง เป็นผู้ลงนามอนุมัติในคำร้องของผู้อื่น และอาจเป็นผู้ประพันธ์ร่วมในผลงานของผู้อื่นได้ในเวลาเดียวกัน

### 1.4 ลำดับผู้ลงนามของเอกสารแต่ละประเภท

ตารางนี้แสดงว่าเอกสารแต่ละประเภทต้องผ่านผู้ลงนามตำแหน่งใดบ้างตามลำดับ ซึ่งเป็นข้อมูลประกอบยูสเคส UC-26 และ UC-36

**ระยะที่ 1 — การขอประเมินผลการสอน**

| เอกสาร | ลำดับผู้ลงนาม |
|--------|---------------|
| แบบคำขอประเมินผลการสอน | ผู้ขอประเมินผลการสอน (A-02) |
| แบบตรวจสอบคุณสมบัติ | ผู้ขอรับการประเมิน (A-02) → นักทรัพยากรบุคคล (A-07) |
| บันทึกเสนอแต่งตั้งคณะกรรมการ | หัวหน้าสาขาวิชา (A-04) → รองคณบดี (A-05) → คณบดี (A-06) → เจ้าหน้าที่บริหารงาน (A-07) |
| คำสั่งแต่งตั้งคณะกรรมการ | คณบดี (A-06) |
| หนังสือเชิญกรรมการ | คณบดี (A-06) |
| แบบประเมินผลการสอน | ประธานคณะกรรมการประเมิน (A-08) |
| แบบสรุปผลการประเมิน | ประธานคณะอนุกรรมการ (A-08) |
| หนังสือแจ้งผลการประเมิน | คณบดี (A-06) |

**ระยะที่ 2 — การขอกำหนดตำแหน่งทางวิชาการ**

| เอกสาร | ลำดับผู้ลงนาม |
|--------|---------------|
| แบบประวัติส่วนตัว | เจ้าของประวัติ (A-02) |
| แบบเสนอขอกำหนดตำแหน่ง | ผู้เสนอขอ (A-02) |
| แบบแสดงหลักฐานการมีส่วนร่วม | ผู้เสนอขอ (A-02) → คณบดี (A-06) |
| แบบรับรองจริยธรรมและจรรยาบรรณ | ผู้เสนอขอ (A-02) → ผู้บังคับบัญชาชั้นต้น (A-04) |
| บันทึกเสนอผลงาน | หัวหน้าสาขาวิชา (A-04) → คณบดี (A-06) |
| หนังสือนำส่งผลงาน | คณบดี (A-06) |
| แบบตรวจสอบเอกสาร | เจ้าหน้าที่ผู้ตรวจสอบ (A-07) → คณบดี (A-06) |
| บันทึกส่งกองทรัพยากรบุคคล | นักทรัพยากรบุคคล (A-07) |
| แบบรับรองการมีส่วนร่วมในผลงาน | ผู้ขอกำหนดตำแหน่ง (A-02) → ผู้ประพันธ์อันดับแรก (A-03) → ผู้ประพันธ์บรรณกิจ (A-03) |

| 8 | | ตรวจสอบว่ามีขั้นตอนการลงนามลำดับถัดไปหรือไม่ |

## 6. หมายเหตุประกอบการจัดทำเอกสาร

1. ยูสเคสที่ไม่มีรหัสกำกับในแผนภาพ เช่น "แจ้งเตือนผู้เกี่ยวข้อง" และ "สร้างไฟล์เอกสาร PDF" เป็นยูสเคสระดับย่อยที่ถูกเรียกใช้ร่วมกันจากหลายยูสเคส แสดงไว้เพื่อความชัดเจนของความสัมพันธ์แบบ include และไม่นับรวมในจำนวน 52 ยูสเคส
2. การอ้างอิงในเอกสารฉบับอื่น เช่น เอกสารออกแบบระบบหรือแผนการทดสอบ ให้อ้างด้วยรหัสยูสเคส เช่น UC-26 แทนการคัดลอกแผนภาพซ้ำ เพื่อป้องกันความไม่สอดคล้องเมื่อมีการแก้ไขภายหลัง
3. หากพื้นที่ในเอกสารจำกัด แนะนำให้แสดงเฉพาะแผนภาพระดับบริบท (หัวข้อ 3.1) ไว้ในบทหลัก และย้ายแผนภาพระบบย่อย (หัวข้อ 3.2 ถึง 3.8) ไปไว้ในภาคผนวก
4. รหัสความต้องการเชิงหน้าที่ (FR) ในตารางหัวข้อที่ 5 เป็นการกำหนดลำดับเบื้องต้น ควรปรับให้ตรงกับรหัสที่ใช้จริงในเอกสารวิเคราะห์ความต้องการของระบบ
5. ระบบรองรับคำร้องสองประเภทที่มีลำดับขั้นการพิจารณาต่างกัน คือ คำร้องขอประเมินผลการสอน และคำร้องขอกำหนดตำแหน่งทางวิชาการ แบบจำลองนี้รวมทั้งสองประเภทไว้ในยูสเคสชุดเดียวกันเนื่องจากมีโครงสร้างการทำงานเหมือนกัน ความแตกต่างของลำดับสถานะแสดงไว้ในเอกสารภาคผนวกเรื่องผังสถานะ
