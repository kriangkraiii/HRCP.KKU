## 1. ข้อมูลและวิเคราะห์สาเหตุ (Problem Analysis & Root Cause)

### 1.1 ปัญหาที่พบ (Current Issue)
จากภาพหน้าจอหน้าลงนามเอกสาร (`/esign/sign/{stepId}`):
* กล่องแสดงตัวอย่างเอกสาร (Document Preview) ฝั่งซ้ายยืดตัวยาวลงมาด้านล่างมากเกินไป
* เกิดพื้นที่ว่างสีขาวขนาดใหญ่ (Huge Empty White Space) อยู่ใต้ตัวอ่าน PDF
* ขอบล่างของการ์ดฝั่งซ้ายถูกดึงลงมาให้เท่ากับปุ่ม "ส่งกลับให้แก้ไข" ของฝั่งขวา

### 1.2 สาเหตุเชิงเทคนิค (Technical Root Cause)
เมื่อตรวจสอบไฟล์ [`src/main/resources/templates/academic/esign/sign.html`](file:///Users/kriangkrai/Developer/Projects/eclipse-workspace/Spring%20pj/pjweb/HRCP.KKU/HRCP-KKU-Academic/src/main/resources/templates/academic/esign/sign.html#L81-L117):

1. **Bootstrap Flex Row Stretch + `h-100`:**
   ```html
   <div class="row g-3">
       <!-- ฝั่งซ้าย: เอกสารตัวจริงที่กำลังจะลงนาม -->
       <div class="col-lg-7">
           <div class="card card-academic h-100 shadow-sm">
   ```
   * กริดของ Bootstrap (`.row`) มีคุณสมบัติเริ่มต้นเป็น Flexbox (`align-items: stretch`) ทำให้คอลัมน์ฝั่งซ้าย (`col-lg-7`) และฝั่งขวา (`col-lg-5`) มีความสูงเท่ากันเสมอ
   * คอลัมน์ฝั่งขวามีการ์ดซ้อนกันหลายใบ (ลำดับการลงนาม + เลือกลายเซ็น + ข้อมูล Digital ID + ความยินยอม + ปฏิเสธการลงนาม) ทำให้ฝั่งขวามีความสูงรวมถึง ~1,400px - 1,800px
   * คลาส `h-100` ที่ใส่ไว้ในการ์ดฝั่งซ้ายบังคับให้ตัวการ์ดยืดตามความสูงของฝั่งขวาจนสุด

2. **ความไม่สัมพันธ์กันระหว่าง Card และ PDF Viewer:**
   * ตัวอ่าน PDF ([`esign_pdf_viewer.css`](file:///Users/kriangkrai/Developer/Projects/eclipse-workspace/Spring%20pj/pjweb/HRCP.KKU/HRCP-KKU-Academic/src/main/resources/static/css/esign_pdf_viewer.css#L8-L9)) กำหนดความสูงไว้คงที่:
     ```css
     .esign-viewer-wrapper {
         height: 78vh;
         min-height: 700px;
     }
     ```
   * เมื่อ `.card-academic` ฝั่งซ้ายยืดไปถึง 1,600px แต่ตัว PDF Viewer สูงเพียง 700px จึงทำให้พื้นที่ที่เหลือ (~900px) ใน `.card-body` กลายเป็น **พื้นที่ว่างสีขาวโล่ง (White Dead Zone)** ทอดยาวลงไปด้านล่างอย่างไม่สวยงาม

3. **ปัญหาการใช้งาน (Usability / Scrolling Issue):**
   * เมื่อผู้ใช้เลื่อนหน้าจอลงไปอ่านข้อตกลงและกดยืนยันการลงนามที่ฝั่งขวา ตัวอย่างเอกสารฝั่งซ้ายจะเลื่อนหลุดออกไปจากหน้าจอ ผู้ใช้จะไม่สามารถดูเอกสารคู่ขนานไปกับการกดลงนามได้

## 2. ทางเลือกในการแก้ไข (Proposed Solutions)

### ทางเลือกที่ 1 (แนะนำ): Sticky Preview ตรึงหน้าจอแบบ Split-View
* **แนวคิด:** เปลี่ยนให้ฝั่งซ้ายเป็น Sticky Card (`position: sticky; top: 1rem;`)
* **ความสูง:** กำหนดความสูงของการ์ดให้พอดีกับหน้าจอ (`height: calc(100vh - 2rem);`)
* **PDF Viewer:** ให้ `.esign-viewer-wrapper` ขยายเต็มพื้นที่การ์ด (`flex: 1; height: 100%;`)
* **ข้อดี:**
  * ไม่มีพื้นที่ว่างสีขาวส่วนเกิน
  * ขณะที่ผู้ใช้เลื่อนดูขั้นตอนการลงนามหรือเลือกลายเซ็นทางฝั่งขวา เอกสารฝั่งซ้ายจะถูกตรึงอยู่กับที่เสมอ ผู้ใช้สามารถตรวจดูเอกสารฉบับจริงได้ตลอดเวลาโดยไม่ต้องเลื่อนจอขึ้น ๆ ลง ๆ

```
+------------------------------------+------------------------------------+
|  [ ฝั่งซ้าย: STICKY PREVIEW ]       |  [ ฝั่งขวา: SCROLLABLE ACTIONS ]   |
|  ความสูงคงที่เต็มหน้าจอ (Viewport)   |  เลื่อนลงได้อิสระ                  |
|  +------------------------------+  |  - ลำดับการลงนาม                   |
|  |                              |  |  - เลือกลายเซ็น                    |
|  |     PDF Viewer ฉบับจริง      |  |  - ข้อมูล Digital ID               |
|  |     (Scroll หน้าเอกสารได้)    |  |  - ความยินยอม                      |
|  |                              |  |  - ปุ่มยืนยันลงนาม / ปฏิเสธ        |
|  +------------------------------+  |                                    |
+------------------------------------+------------------------------------+
```

### ทางเลือกที่ 2: ยกเลิก `h-100` ให้การ์ดสูงตามเนื้อหาจริง (Natural Auto Height)
* **แนวคิด:** ปลดคลาส `h-100` ออกจากการ์ดฝั่งซ้าย
* **ผลลัพธ์:** การ์ดฝั่งซ้ายจะสูงเท่ากับความสูงของ PDF Viewer (~78vh) และจบลงตามจริง โดยด้านล่างปล่อยเป็นพื้นหลังเทาของหน้าเว็บทั่วไป ไม่เกิดกล่องการ์ดขาวยืดยาว
* **ข้อดี:** ทำได้ง่ายมาก เปลี่ยนแปลงโค้ดน้อยที่สุด

### ทางเลือกที่ 3: ยืด PDF Viewer ให้เต็มความสูงของการ์ด (Full-Height Flex Expansion)
* **แนวคิด:** คง `h-100` ไว้ แต่ปรับแต่ง CSS ให้ `.card-body` และ `.esign-viewer-wrapper` ขยายตัวเต็ม 100% ของคอลัมน์
* **ผลลัพธ์:** ตัวกรอบสีเทาเข้มของ PDF Viewer จะยืดยาวลงมาเต็มความสูงเท่ากับฝั่งขวา
* **ข้อเสีย:** บนหน้าจอที่มีคอลัมน์ขวายาวมาก ตัว PDF Viewer จะมีขนาดใหญ่เกินกว่าหน้าจอคอมพิวเตอร์ทั่วไป
