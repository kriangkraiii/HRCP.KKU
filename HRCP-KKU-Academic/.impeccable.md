# HRCP-KKU Academic — Design Context

## Design Context

### Users
- **Faculty/Lecturers** applying for academic positions (ผู้ช่วยศาสตราจารย์, รองศาสตราจารย์, ศาสตราจารย์)
- **HR Staff** (เจ้าหน้าที่ฝ่ายบุคคล) who manage petition workflows
- **Committee Members** who review and approve applications
- **Tech Comfort:** Very high — College of Computing, KKU. Users are CS professionals.
- **Context:** Desktop-primary, working at their desk. Petitions are multi-step processes spanning days/weeks.
- **Job to be Done:** Submit, track, and manage academic position petitions with confidence that nothing is lost or delayed.

### Brand Personality
**Reliable · Formal · Efficient** (น่าเชื่อถือ · เป็นทางการ · มีประสิทธิภาพ)

- **Voice:** Professional, clear, direct. No unnecessary decoration.
- **Tone:** Calm authority — "the university system that just works."
- **Emotional goal:** Users should feel confident the process is under control, and find the system pleasant to use despite being institutional.

### Aesthetic Direction
- **Visual tone:** Institutional-modern. Formal enough for a university, modern enough to feel current.
- **Reference:** [antigravity.google](https://antigravity.google/) — clean structure, purposeful motion, premium feel without being flashy.
- **Current palette:** Navy gradient (#0d1b3e → #1a237e → #0d47a1) with blue accent (#42a5f5). Open to evolution while maintaining academic authority.
- **Typography:** Sarabun — the standard Thai academic typeface. Keep it.
- **Theme:** Light mode primary, dark mode supported.
- **Anti-references:** Anything that feels hard to use or unpleasant. No visual clutter, no confusing navigation, no walls of text without hierarchy.

### Design Principles

1. **Clarity over decoration** — Every element must serve a purpose. If it doesn't help users complete their task, remove it.
2. **Status at a glance** — Users check petition status frequently. Progress, current state, and next steps must be visible without clicking.
3. **Institutional trust** — The design must feel like an official university system, not a consumer app. Professional color palette, structured layouts, clear data presentation.
4. **Effortless efficiency** — Tech-savvy users expect fast interactions. Minimize clicks, use progressive disclosure, make common actions prominent.
5. **Accessible formality** — Formal doesn't mean cold. Warm the neutrals, use clear Thai typography, and provide helpful guidance at decision points.

### Technical Constraints
- **Framework:** Spring Boot 3 / Thymeleaf (server-rendered, not SPA)
- **CSS:** Vanilla CSS with Bootstrap 5.3.3 utility classes. No build tooling for CSS.
- **Token system:** 46+ CSS custom properties in `:root` for colors, motion, layout.
- **Accessibility:** WCAG AA compliance, `prefers-reduced-motion` respected, ARIA landmarks.
- **Localization:** Thai-primary with Google Translate toggle for English.
